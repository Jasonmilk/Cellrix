## 序言：从"模拟界面"到"物理真实"

当前数字界面的根本缺陷在于：用非确定性的工具（CSS、JS、DOM）去描述物理事实（像素、电量、屏幕）。这导致了无尽的资源浪费与认知负担。

Cellrix 协议的根本假设是：界面应当在逻辑上是纯符号的数学演算，在物理上是可降级的现实映射。本宪章确立了三项不可动摇的最高法则，作为所有实现与扩展的准绳。

## 第一部分：三大物理法则（不可变基座）

| 法则编号 | 法则名称 | 严格定义（v1.1.0 修订版） |
|---|---|---|
| 法则 I | 纯符号契约（Pure Symbolic Contract） | 逻辑层之间的一切通信（结构、状态、事件）必须使用预定义的符号字典（详见第三节）。任何人类自然语言字符串（含中文、英文、数字显示）仅允许出现在 display 映射表中，严禁参与逻辑判断与路由。 |
| 法则 II | 逻辑态确定性（Logical State Determinism） | 给定一个初始 SemanticSnapshot 与一个按全局逻辑时间戳排序的 MUTATE 补丁序列，任意合规的 Cellrix 渲染器（无论版本、平台、线程）执行后，必得到完全字节一致的最终**逻辑态（Logical State）**。逻辑态特指结构树与符号属性（JSON/二进制），不包含像素颜色、帧率、动画曲线等物理输出。 |
| 法则 III | 物理层主权与呈现自由（Physical Sovereignty） | 物理渲染器（位于用户设备端）拥有绝对物理主权。它有权根据本地实时物理约束（电池电量、CPU负载、屏幕密度、环境光照、色盲模式）自主决定"如何将逻辑态映射为像素/触感/声音"。逻辑层只能发送 fidelity 请求，物理层有权做**静默降级响应**，且此决策无需同步回逻辑层。法则 II 约束"乐谱"（逻辑），法则 III 约束"演奏"（物理）。 |

## 第二部分：双宇宙架构（逻辑宇宙与物理宇宙）

Cellrix 是一个严格解耦的"双宇宙"系统，两者仅通过一个标准化接口通信。

### 2.1 逻辑宇宙（The Logic Universe）

- **存在形式**：纯数据（JSON/二进制）。
- **语言**：数学符号、代数数据类型（ADT）。
- **核心职责**：维护全局逻辑状态树、处理补丁代数（MUTATE）、广播意图（Intent）。
- **无知之处**：完全不知道屏幕长宽、像素密度、语言、电池。它只处理 Symbols 和逻辑时间（T轴）。

### 2.2 物理宇宙（The Physical Universe）

- **存在形式**：运行中的原生进程（Kotlin/Swift/Rust）。
- **核心组件**：物理适配器（Physical Adapter）。
- **核心职责**：监听操作系统信号（电量、刷新率、系统主题）、解析符号协议、执行命中测试将物理坐标转为 NodeID。
- **无知之处**：完全不知道"业务逻辑"是什么。它只处理 Pixels、Haptics 和 Audio。

### 2.3 标准接口（唯一耦合点）

```typescript
interface RenderRequest {
  snapshot: LogicalSnapshot;    // 逻辑产物（全量或增量检查点）
  delta?: Patch[];              // 可选的待应用补丁列表
  fidelity_hint: FidelityLevel; // 逻辑期望 (MAX | BALANCED | MINIMAL)
}

interface RenderResponse {
  events: UserIntent[];         // 用户触碰映射后的符号事件（上行）
}
```

## 第三部分：符号字典（Symbolic Lexicon）—— 确定性之锚

视觉属性（颜色/字体/间距/动画曲线）被彻底移出本字典，全权归入 display 映射表或 fidelity_hint 附属参数。

逻辑符号层仅包含以下 **12 个核心保留字**：

### 3.1 结构类型符号（6个）

- **CONTAINER**：容器（用于布局分组）
- **ACTION**：可交互动作节点（按钮、点击区域）
- **INPUT**：输入捕获节点（文本框、滑块）
- **DISPLAY**：纯展示节点（文本、图片）
- **SCOPE**：带隔离边界的复合组件（黑盒）
- **SPACER**：占位填充节点（用于弹性布局）

### 3.2 空间布局符号（5个）

- **AXIS_H / AXIS_V / AXIS_Z**：分别对应 X, Y, Z 轴排列。
- **ALIGN_CENTER**：居中对齐标量（适用于主轴或交叉轴）。
- **FILL**：填充剩余空间（尺寸约束意图）。

### 3.3 交互触发符号（1个）

- **ACTIVATE**：用户确认触发的标准事件（点击/回车/语音确认）。

**边界定义**：任何超出这 12 个符号之外的"描述"，均为视觉辅助数据（如 hex_color、font_size、ease_in_out），必须放置在节点的 display.meta 或 fidelity_hint.params 中，逻辑引擎无视它们的存在。

## 第四部分：补丁代数（Patch Algebra）—— 活的像素推拉逻辑

状态变更不传输完整 UI，只传输补丁运算符。（v1.1.0 修正：废除 MOVE，引入 TAKE + PLACE）

### 4.1 支持的运算符（Operators）

| 操作符 | 签名 | 幂等性说明（v1.1.0） |
|---|---|---|
| INSERT | (path, node) | 若路径已存在，则拒绝插入并报错（防止覆盖）。 |
| DELETE | (path) | 若路径不存在，则静默成功（无操作）。 |
| UPDATE | (path, props) | 若路径不存在，则静默成功（无操作）。 |
| REPLACE | (path, node) | 若路径不存在，则等价于 INSERT。 |
| TAKE | (from_path) | 替代原 MOVE。从源路径提取节点（剪切），若源不存在则静默成功（无操作）。返回被提取的节点。 |
| PLACE | (to_path, node) | 替代原 MOVE。将节点放置到目标路径（覆盖式写入），若目标已有则强制覆盖（等同于 DELETE+INSERT）。 |

### 4.2 幂等性与确定性保障

- 任意单个操作符应用两次，结果与应用一次完全相同（如 DELETE 已删除节点、PLACE 覆盖相同节点）。
- 逻辑态的最终确定性由操作符序列的全局顺序保证，而非依赖操作符内部的判断逻辑。

## 第五部分：全量-增量双轨制（v1.1.0 新增章节）

为解决 CPPC 补丁代数与现有 SemanticSnapshot 的关系问题，确立以下同步规则：

1. **初次握手**：物理层与逻辑层建立连接时，逻辑层必须传输一份完整的 SemanticSnapshot（全量快照）。
2. **稳态运行**：后续状态变更仅通过 MUTATE 补丁传输（增量）。
3. **逻辑检查点（Logical Checkpoint）**：
   - 每累计应用 100 个补丁，或每经过 5 分钟（以逻辑时间戳为准），逻辑层必须向物理层发送一份新的全量 SemanticSnapshot。
   - 物理层收到检查点后，**截断（Truncate）**本地 WAL 日志至该检查点，防止日志无限膨胀。
4. **断线重连**：物理层若检测到本地 WAL 落后于逻辑层提供的检查点序列号，则主动请求全量快照，放弃回放旧补丁。

## 第六部分：物理层适配器与降级策略（物理事实优先）

这是 Cellrix 区别所有现有框架的核心机制。

### 6.1 物理上下文读取（Physical Context）

物理层必须（或可选）读取以下传感器/系统数据：

- **Battery**：电量百分比（0.0 - 1.0）。
- **Thermal**：CPU 温度状态（NOMINAL | THROTTLED | CRITICAL）。
- **Display**：刷新率（Hz）、逻辑密度（dp）、对比度（Contrast）。
- **Accessibility**：是否开启"减少动画"、"高对比度"、"大字体"。

### 6.2 确定性降级映射表（Degradation Matrix）

| 逻辑请求（Fidelity Hint） | 物理条件（Battery/Performance） | 物理层行动（实际输出） |
|---|---|---|
| MAX (要求120fps+阴影) | 电量 < 20% 或 发热 | 静默降级：关闭阴影，强制锁定 60fps。不回传协议错误。 |
| BALANCED | 低电量模式开启 | 极简渲染：移除所有 opacity 过渡动画，使用纯色块替代高斯模糊。 |
| MINIMAL | 任意条件 | 直接输出原生系统控件（TextView/Button），零额外绘制开销。 |

## 第七部分：上行意图映射（物理触碰 → 逻辑符号）

用户点击屏幕时，Cellrix 必须完成"物理坐标 → 逻辑符号"的转换，而非传递原始坐标。

1. **命中测试（Hit-Testing）**：物理渲染器维护一棵**空间哈希树（Spatial Hash Tree）**，将屏幕点击坐标（X, Y, Z）映射到具体的 NodeID。
2. **符号打包**：物理层将 NodeID + 操作类型（ACTIVATE / CHANGE）打包为标准的 INTENT-7 事件负载。
3. **传输**：通过 CI-144/Bind-19 的上行通道发送回逻辑宇宙。

## 第八部分：安全、身份与持久化（附属绑定）

- **会话持久性**：所有 MUTATE 补丁必须追加写入设备本地 WAL（Write-Ahead Log）。应用被杀后重启，物理层重放 WAL 即可确定性复原至崩溃前逻辑态。
- **符号层权限**：每个 SCOPE 节点必须携带 capability_required 符号。若物理层检测到当前会话无此符号（CAPABILITY-13 验证失败），直接拒绝渲染该子树，显示通用占位符。
- **内容映射（i18n/A11y）**：display 映射表支持 en、zh、emoji、tts_phoneme。物理层根据系统 Locale 自动选择。核心逻辑依然只认 label_key。

## 第九部分：宪章符合性测试（The "Cellrix Test"）

一个渲染器实现若要声称"符合 CPPC v1.1.0"，必须通过以下三项硬性单元测试：

1. **符号隔离测试**：在逻辑层输入 label_key: "HELLO"，物理层即使未配置任何 display 映射，系统必须稳定运行且绝不崩溃（默认显示空字符串或占位符）。
2. **逻辑态时间回溯测试**：连续发送 1000 个随机 MUTATE 补丁（含 TAKE/PLACE），记录最终逻辑态 S_n。重置初始状态，逐条重放补丁，重放后的逻辑态必须与 S_n 字节一致。
3. **物理降级测试**：在模拟低电量（<10%）环境下，逻辑层发送 fidelity: MAX。物理层输出的帧率必须被限制在 ≤ 60fps，且不向逻辑层报告任何错误或异常。
