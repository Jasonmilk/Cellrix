## 一、这是什么

### 1.1 一句话

**Web 面板的视图区域必须是协议 `GridDefinition` / `GridSlot` 的投影**，
而不是一张外挂的手写 HTML 页面。

### 1.2 为什么需要（可证的物理事实）

**Cellrix 自己的协议 crate 早已定义网格与槽位**：

| 类型 | 位置 | 作用 |
|---|---|---|
| `LayoutHints` | `protocol/src/manifest.rs:36` | 面板偏好 + 网格定义 |
| `GridDefinition` | `protocol/src/manifest.rs:43` | `rows: Vec<GridSlot>` |
| `GridSlot` | `protocol/src/manifest.rs:49` | `{ id, constraint }` |
| `SlotConstraint` | `protocol/src/manifest.rs:56` | `Percentage` / `FixedLines` / `Min` |
| `SemanticNode.slot_binding` | `protocol/src/snapshot.rs:38` | 节点 → 槽位绑定 |
| `NodeType::Unknown` | `protocol/src/snapshot.rs:45-54` | `#[serde(other)]` 宽容降级 |
| `ViewHash.slot_bindings` | `protocol/src/view_hash.rs:14` | 节点→槽位映射的签名基准 |

**使用者实测**：

| crate | 使用协议网格模型 |
|---|---|
| `protocol` | ✅ 定义者 |
| `layout` | ✅ 纯数学布局引擎 |
| `mock-agent` | ✅ 测试夹具 |
| **`web`** | ❌ **0 个文件** |

**TUI 路径**走「协议 `GridDefinition` → 布局引擎 → `ui`」，即**碳硅同构**
（`DNA.md:23-26`：人类看到的视觉布局 = AI 看到的语义拓扑图，不允许"人类可见但
AI 不可寻址"的元素）。**`cellrix-web` 整体绕开了协议模型。**

> **这就是"界面凭凑式"的根因**：不是缺 slot 系统，而是 **Web 面板没有成为协议投影**。

### 1.3 宿主现状：23 重字符串替换

`web/src/main.rs` 的 `index_html()`：

- 24 个 `include_str!` 常量
- **23 次链式 `.replace("__XXX__", ...)`**
- 占位符清单住在 `base.html`（83 行 / 23 个洞 = 22 资产 + 1 派生 `__REFRESH__`）

新增一个视图要改 **5 处**（资产 / `include_str!` / `.replace()` / 挖洞 / 切换按钮）。

### 1.4 边界：UI 层 vs 数据层

| 层 | 归属 | 现状 |
|---|---|---|
| **数据装配** | `web/assets/assembly.js`（`ADR-0018`） | ✅ **已有，自主血统**：一条磁带多 target、幂等 upsert、`deriveCoordinates()`、`digest()` |
| **UI 投影** | **本文件** | ⬜ 缺口所在 |

`assembly.js:5` 原文「a target never reads the tape itself (D5)」——**本契约把同一
原则从数据层上推到 UI 层**：视图不读业务态，只读**静照**。

> **身份红线**：本生态的 **`证轨`（ProveTrack）** 是证据轨道，**永不写作「轨迹」**。

## 三、四种槽位形态

一个槽位**必须**声明为且仅为一种形态。形态决定"谁可以占用它、如何渲染"。

| 形态 | 占用者 | 渲染语义 |
|---|---|---|
| **单槽** | 恰好一个 | 占用或无占用（显式空态） |
| **序列槽** | 有序若干 | 按序位渲染全部 |
| **键控槽** | 按 key 派发 | 同 key 唯一，按 key 取用 |
| **选举槽** | 自荐若干 | 按优先级选举，首个非空当选；全空落兜底 |

### 3.1 单槽（single）

恰好一个占用者。无占用时渲染声明的空态，而非空白。

**在册**：`shell.head`、`shell.foot`、`shell.eco`、`view.cockpit`、`view.chat`、`view.flows`

### 3.2 序列槽（list）

有序条目集。顺序是**语义**而非偏好——渲染必须保序。

**在册**：`shell.bar.view-switch`（视图切换按钮）、`view.prove-track.side`（经历列表）

> 顺序由**声明的序位**决定，**不得**由加载到达顺序决定——与 `ADR-0018` 的
> `deriveCoordinates()`（turn 序号数 tape，不数到达顺序）同源。

### 3.3 键控槽（keyed）

按 key 派发。**同 key 第二次占用即失败**（不静默覆盖）。键空间**运行期开放**：
契约声明**槽位**，从不声明全部**键**。故必须有兜底路径。

**在册**：`shell.views`（按视图 id 派发：`cockpit` / `prove-track` / `chat` / `flows`）

### 3.4 选举槽（chain）

按 **priority 升序**选举，同优先级按登记顺序；**首个返回非空者当选**；
全空则落父槽声明的兜底。

**在册状态**：**已声明，暂无占用者**（诚实记录，不虚构用例）。

**候选（T3+ 评估）**：证轨节点渲染器——按节点 `NodeType` 自选举，兜底为通用渲染器。
与协议 `NodeType::Unknown` 的降级链同构。

## 四、四份（The Four Shares）

占用者写一个视图组件，组件**只读四份**，每份有唯一来源。

| 份 | 内容 | 来源 |
|---|---|---|
| **运行份** | 父槽传入的持有者上下文、生态点亮、连接态 | 父槽渲染调用点 |
| **渲染份** | 本槽**已开槽**的子槽渲染入口 | 本槽的开槽声明 |
| **存储份** | 本槽声明的静照座位：读经选择器、写经烘焙动作 | `defineStill` 声明 |
| **业务份** | 注入工厂返回的业务面 | 注入工厂声明 |

### 4.1 铁律

1. 组件**引用四份**，**不得**自行重定义任一份
2. 写入**只能**经存储份的烘焙动作；**禁止**直写业务态
3. 业务数据（事件窗、流式累积、待定交互）**一律**在 `assembly.js` 对象层
4. 槽位私有状态**仅限**纯视图态：滚动位置、搜索文本、展开折叠

### 6.4 与协议槽位的对应（T1b 建立）

清册中的槽位名将在 T1b 与协议侧对齐：

- 槽位名取自 / 对应 `GridSlot.id`（`protocol/src/manifest.rs:49`）
- 语义节点经 `slot_binding`（`protocol/src/snapshot.rs:38`）绑定到槽位
- `view_hash.slot_bindings` 可在 Web 面板侧计算，使 **TUI 与 Web 面板共享同一
  共识锚点**（`CAPABILITY-13` PC-2 的"所见即所签"）

> **待决策**：T1b 的投影深度——只做名对应，还是同时接通 `view_hash`（见 `ADR-0021` §九）。

### 6.5 何时新增槽位

只有**新区域**才新增槽位。**新视图不是新槽位**——新视图是 `shell.views` 的**新键**。

这条区分是收掉"加视图改 5 处"的关键：新视图 = 一张皮片落一个已有键。

## 八、起搏图数据格式（契约）

**起搏图**是装配图，必须是**数据**，不得是宿主 Rust 代码里的常量列表。

### 8.1 形状

```json
{
  "version": "1.0.0",
  "stage": "T1a",
  "template": "base.html",
  "pieces": [
    { "id": "cockpit", "placeholder": "__COCKPIT__", "asset": "cockpit.html" }
  ],
  "derived": [
    { "placeholder": "__REFRESH__", "source": "refresh_secs" }
  ]
}
```

> **T1a 现状**：`pieces` 按序展开占位符，`derived` 在全部皮片展开后
> 对整体应用**一次**（链式替换语义，见 §9.1 的陷阱）。

### 8.2 字段

| 字段 | 含义 | 必填 |
|---|---|---|
| `version` | 契约版本 | ✅ |
| `stage` | 阶段标记（`T1a` / `T1b`） | 可选 |
| `template` | 模板资产名 | ✅ |
| `pieces[].id` | 皮片唯一 id | ✅ |
| `pieces[].placeholder` | 目标占位符 | ✅ |
| `pieces[].asset` | 皮片资产名 | ✅ |
| `pieces[].slot` | **T1b 新增**：目标槽位名 | T1b ✅ |
| `pieces[].key` | **T1b 新增**：键控槽的 key | 键控时 ✅ |
| `derived[].placeholder` | 派生值占位符 | ✅ |
| `derived[].source` | 派生源键（无对应即硬错，不得静默空串） | ✅ |

### 8.3 资产送达

皮片按需送达：`GET /assets/<piece>.js`。**不引入构建步骤**（`ADR-0016` D7）。

## 九、装配期校验（T2 目标，本契约先定规则）

**错误必须在装配期失败，且指名缺谁**——取代当前运行期 `throw` + 人肉注释。

| # | 规则 | 违反时 |
|---|---|---|
| V1 | 占用必须落在**已开槽**的槽位 | 拒绝：未申报槽位 |
| V2 | 开槽**不得重复** | 拒绝：重复声明 |
| V3 | **单槽**不得有两个占用者 | 拒绝：多占 |
| V4 | **键控槽**同 key 不得两次占用 | 拒绝：撞键 |
| V5 | 依赖必须存在且**无环** | 拒绝：缺依赖 / 环 |
| V6 | `shell.views` 键集 **=** `shell.bar.view-switch` 条目集 | 拒绝：壳键不一致 |
| V7 | 槽位名与皮片 id 均**唯一** | 拒绝：重名 |
| V8 | 键控/选举槽必须有 `fallback` | 拒绝：无兜底 |
| V9 | **未知视图键**必须有降级渲染 | 拒绝：无降级（对齐 X1） |

### 9.1 已捕获的陷阱（T1a 实测）

`script.html` 内含 `__REFRESH__`，故**派生值必须在宿主皮片展开之后对整体应用一次**。
老代码的 23 次链式 `replace` 依赖此语义；单遍模板替换会把字面量留在页面上。
已由 `boot::tests::derived_applies_after_its_host_piece` 守卫。

### 9.2 诚实记录的约束

`include_str!` 要求字符串字面量，故「资产名→字节」的嵌入清单**必然**留在
`web/src/boot.rs`（Rust），无法由起搏图动态取。
**图管装配顺序与映射，清单管嵌入内容。** 新增资产 = 1 行清单 + 1 条图项。
若要消除清单行，需引入 `include_dir!` 类宏（另议）。

## 十、诚实边界（本契约不做什么）

| 不做 | 理由 |
|---|---|
| 引入 React / 插件运行时 / npm 运行时依赖 | 违反零构建依赖（`ADR-0016` D7）与 DNA 铁律 2 |

| 自造与协议重复的词汇 | 违反 DNA「极致复用：不重新发明」（v1 之错） |
| 在本契约内改任何代码 | T0 是纯契约，实现属 T1b–T5 |
| 用"轨迹"指代"证轨" | **身份红线** |

**已知代价**：不引 React ⇒ 拿不到类型级槽位契约。**自觉取舍**，换零依赖与 400 行红线。

- [ ] 扩展保留区（§五）与冻结面（§七）均已声明
