## 一粒种子的自白

### 为什么需要 Cellrix？

传统的终端 UI（TUI）和图形界面是为碳基视觉感知设计的。它们渲染像素或原始字符，使用绝对坐标。当硅基智能体（AI）与它们交互时，面临两个根本性问题：

1. **理解鸿沟**：AI 必须解析杂乱的、非标准的文本转储，或执行昂贵的视觉 OCR，才能理解屏幕上的内容。
2. **交互摩擦**：AI 无法直接"点击"一个语义元素，必须模拟鼠标坐标或键盘快捷键，这些都是为人类设计的，不是为 AI 设计的。

**Cellrix 弥合了碳基与硅基心智之间的理解鸿沟。**

### Cellrix 是什么？

Cellrix 不是另一个 TUI 库。它是一个**意图驱动、确定性、空间语义的终端 UI 协议和高性能运行时**。

通过将终端屏幕不视为原始画布，而是视为**确定性的、语义化的单元格网格**，Cellrix 实现了双方面的空间语义范式：
- **对人类眼睛**：它呈现遵循 **Somatic Monasticism（身体苦修主义）** 美学的、响应式的视觉布局。
- **对硅基智能体**：它暴露确定性的语义节点拓扑图（`CIN7`），允许智能体无需视觉摩擦或屏幕抓取即可导航、检查和交互。

### Cellrix 的独特价值

| 维度 | 传统 TUI | Cellrix |
|---|---|---|
| 人类视觉 | ✅ 优秀 | ✅ 优秀（Somatic Monasticism 美学） |
| AI 语义理解 | ❌ 需要 OCR/文本解析 | ✅ 确定性语义拓扑图 |
| 多客户端 | ❌ 单进程绑定 | ✅ Wayland 风格 UDS 多路复用 |
| 后台节能 | ❌ 完整反序列化 | ✅ 零堆分配标签窥探 |
| 协议标准化 | ❌ 各自为政 | ✅ CI-144 协议家族（CIN7/CIC13/CIB19） |

## 一、哲学基础

### 1.1 碳硅同构

Cellrix 的核心哲学是**碳硅同构**——同一帧同时服务人类视觉和 AI 语义。

这不是"为 AI 额外提供一个 API"，而是从根本上重新设计 UI 的表示方式：每个 UI 元素都是一个可寻址的语义节点，它的视觉呈现和语义描述是同一枚硬币的两面。

### 1.2 Somatic Monasticism 美学

Cellrix 的视觉设计遵循 **Somatic Monasticism（身体苦修主义）** 美学：
- 安静、高对比度、低能耗的调色板
- 颜色代表系统状态，从不装饰
- 极简主义，去除一切不必要的视觉元素

调色板：
- **Volcano Base Background**：`#18181A`
- **Paper White Text**：`#E4E4E7`
- **Monastic Indigo Highlight**：`#5B5FC7`（活跃推理、聚焦状态）
- **Alert Amber**：`#D08770`（高风险动作、禅模式）
- **Slate Gray secondary**：`#71717A`

### 1.3 确定性优先

Cellrix 的所有设计都遵循**确定性优先**原则：
- 固定偏移、固定结构、无分支、无堆分配在热路径
- 语义节点 ID 是确定性的，非随机生成
- 布局引擎是纯数学，无副作用
- 视图哈希（view_hash）允许 AI 确定性地检测变化

## 二、架构设计

### 2.1 Workspace 架构

Cellrix 采用 workspace 架构，分为 5 个解耦的 crate：

```
cellrix/ (Workspace Root)
├── cellrix-protocol/ (`protocol`)   # CIN7/CIC13 对齐。零依赖，100% WASM 兼容。
├── cellrix-layout/   (`layout`)     # 纯数学布局引擎 & DFS 焦点管理器。WASM 绑定。
├── cellrix-ui/       (`ui`)         # 模块化 UI。AppState 与 Crossterm IO 解耦。
├── cellrix-transport/(`transport`)  # 多路复用 UDS/Stdio 显示服务器，CIB19 看门狗。
└── cellrix-cli/      (`cli`)        # 命令行工具启动器 (cx)。
```

### 2.2 分层模型

| 层 | 定位 | 核心价值 | 关键机制 |
|---|---|---|---|
| **L1 协议层** | CIN7/CIC13/CIB19 语义协议 | 碳硅共享的语义标准 | 256 节点硬限制、1MB 内容限制、19 秒心跳 |
| **L2 布局层** | 纯数学布局引擎 | 确定性空间分配 | DFS 焦点管理、槽位分配器、禅模式 |
| **L3 渲染层** | 模块化 UI 渲染 | 人类视觉呈现 | Crossterm TUI、主题系统、组件库 |
| **L4 传输层** | 多路复用显示服务器 | 多客户端并发 | UDS/Stdio/TCP、CIB19 看门狗、40 秒超时 |

### 2.3 Wayland 风格多客户端复用

与传统的绑定到单进程的 TUI 不同，`cellrix-transport` 实现了 **UDS 多路复用守护进程**。Cellrix 充当 Wayland 风格的显示服务器（接受连接），而智能体作为客户端被动连接。

- **活动客户端（聚焦中）**：Cellrix 对传入的 `AgentEvent::Snapshot` 执行完整的高速反序列化。
- **非活动客户端（后台）**：Cellrix 使用 `serde::de::IgnoredAny` 执行**轻量级标签窥探**。它完全跳过庞大的快照体——导致**绝对零堆分配**——并安全地从套接字缓冲区中排出原始字节，防止后台客户端线程阻塞。

## 三、契约规范

### 3.1 CI-144 协议家族对齐

Cellrix 是 **CommonIntents-144 (CI-144)** 协议家族的官方参考实现：

#### CIN7 (INTENT-7)
- 定义意图模式，将快照结构化为 7 个核心语义字段
- 强制 **256 节点**硬限制和每节点 **1MB 内容**限制，防止资源受限设备上的 DDoS 和内存耗尽（OOM）

#### CIC13 (CAPABILITY-13)
- 管理能力授权和确认
- 显示服务器拦截焦点切换，并路由下游 `sys_suspend` 和 `sys_resume` 命令，允许智能体执行本地自我节流

#### CIB19 (BIND-19)
- 建立传输绑定
- 强制 **19 秒**质数心跳间隔（防止多智能体网络共振）
- **40 秒**客户端超时阈值

### 3.2 AgentEvent 契约

智能体通过 `AgentEvent` 与 Cellrix 通信：

| 事件类型 | 说明 |
|---|---|
| `Snapshot` | 完整语义快照（活动客户端接收完整反序列化） |
| `Action` | 智能体请求的动作（如焦点切换、内容更新） |
| `Heartbeat` | 19 秒心跳（CIB19 看门狗） |
| `Suspend` | 智能体请求挂起（后台自我节流） |
| `Resume` | 智能体请求恢复 |

### 3.3 语义节点契约

每个语义节点遵循 CIN7 规范：

```json
{
  "id": "text_1",
  "node_type": "text_panel",
  "slot": "main",
  "content": "...",
  "coords": {"row": 0, "col": 0, "height": 10, "width": 80},
  "interactive": true,
  "metadata": {}
}
```

## 四、安全模型

### 4.1 资源限制

- **256 节点硬限制**：防止恶意智能体创建无限节点导致 OOM
- **1MB 内容限制**：每节点内容不超过 1MB
- **40 秒超时**：无响应客户端自动断开
- **19 秒心跳**：检测僵尸客户端

### 4.2 能力授权

- CIC13 管理能力授权和确认
- 显示服务器拦截焦点切换，防止后台客户端窃取焦点
- `sys_suspend`/`sys_resume` 允许智能体自我节流，但不允许影响其他客户端

### 4.3 与 Tuck 的对接

Cellrix 作为 Helix 生态的皮肤，需要与 Tuck（免疫系统）对接：
- 消费 Tuck 的审计日志，展示安全事件
- 展示 Tuck 的决策结果（Pass/Reject/HITL/HardOverride）
- 展示 PFP 物理特征（Risk-Level/Modality/Stance/Proximity-Edge）
