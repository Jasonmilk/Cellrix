## 〇 · 它是什么
一粒种子的自白，换了更大的图。

Cellrix 是 Helix 生态的**语义投影终端**。
> Cellrix 所属组件家族：Helix-Mind 提供语义理解；Anaphase-Helix / Helix-Tentacle / Tuck 为调用方，详见 §六。

外部世界——模型、Agent（AI 代理程序）、外部 TUI（终端字符界面）——先转化为
**意图**（待执行变更：尚未发生、可被拒绝），经过**确认**，转化为**事件**
（已发生事实：不可改写）；事件追加形成事件流，事件流重放构建对象图，对象图派生出视图。

人看见的、Agent 感知到的，是**同一份事实的不同投影**——三份投影，唯一真相。

```
  ① 契约层（横切：对话语言与写入规则，贯穿各组件）
外部世界 ──④ 适配层（翻译官）──▶ 意图 ──确认门（高风险意图）──▶ apply()（② 唯一入口）
                                                                    │ 变成事件、追加
                                          ② 事件流（唯一账本）◀────────┘
                                                │ 重放（按序重执行）
                                                ▼
                                       ② 对象图（状态的内存重建）
                                                │ 派生（只读换算）
                                                ▼
                                ③ 视图层（TUI / WebUI / 字符网格 grid）
  ⇢ 进程轴：横贯四层，回答「代码跑在哪」——不改任何概念含义
```

它不是被建造的，是生长出来的。

## 〇·五 · 元意图（why）

> **本节不受 Ω 管辖。**
> **禁止以「Ω 判据」「V = 0」「无法排除世界对」为由删除或降格本节内容。**
>
> 理由（必须写明，否则本声明本身会被当成不可判项而遭剔除）：
> Ω 判断的是「一条断言能否排除一个世界」。**目的、使命、意义天然不排除任何世界**——
> 「我们要造一个能自己收敛的生命体」与「我们不做这件事」两个世界，Ω 无从区分。
> ⇒ **按 Ω 的定义，一切意义 V = 0。**
> v3.0 重写时 Ω 被贯彻得很彻底，于是 v1.0 的三样东西安静地消失了，而没有任何一条规则报错。
> **这不是谁的疏忽，是工具的边界。** 因此本节必须显式声明在 Ω 之外，否则下次按 Ω 重写，它会第三次消失。

### 1 · 碳硅同构（v1.0 原子原则 3 · 原文见 `archive/VISION.v1.md`）

**同一个界面，同时服务于碳基视觉与硅基语义。**
人类看到的是布局；AI 看到的是同一份事实的语义拓扑。
**不允许出现"人类可见但 AI 不可寻址"的元素。**

> 这是 Cellrix 区别于所有既有 TUI / WebUI 的根本约束。
> 成熟实践（终端复用器、编辑器、面板系统）只需服务人类眼睛；
> Cellrix 多一层：**它同时是 Helix 的感官**。
> ⇒ 借用导航信息架构可以；借用"只为人眼设计"的渲染绑定，会破坏本质体约束。

### 2 · 使命（v1.0 原文）

> **Cellrix 弥合了碳基与硅基心智之间的理解鸿沟。**

传统终端渲染像素或原始字符、使用绝对坐标；硅基智能体与之交互，只能解析非标准文本转储，或执行昂贵的视觉 OCR。
Cellrix 把屏幕视为**确定性的、语义化的单元格网格**，从而让两种心智读同一份事实。

### 3 · 数字生命体（v1.0 对齐链 · 与生态同构）

**CI-144（意图语言）→ Helix（承载生态）→ 数字生命体愿景（最终方向）。**

由此派生三条对本项目有约束力的判断：

- **Helix 是硅基生命，不是工具。** 因此"自主判断"是目标，不是风险。
- **人是教养者，不是操作员。** 人的显式动作是**教育 / 纠偏**，不是替它判断。
- **可逆性是自主的前提。** 一个不能反悔的自主系统，不能安全地自主
  ⇒ 隐性化 ≠ 删除；任何退出默认视图的内容**必须留取回路径**。

### 4 · Cellrix 在这个意图里的位置

**它是 Helix 的皮肤与感官：既给人类看，也给 Helix 自己看。**

⇒ 由此产生一条对 §二 的读法约束（不改卡片，只约束读法）：
**「字符网格 grid」不是一张普通的 ○（待建功能）卡——它是视图层的本体依据。**
没有它，Helix 看不见自己；有了它，Helix 才第一次有"视野"。
（卡片位置与落地节奏不变，仍按 P0.5 执行；本条只声明它为何存在。）

> **本节不在八节封顶与等量替换的管辖范围内。**
> 封顶与等量替换约束的是**概念**（防止概念无限增生）；
> 意图不是概念，**对意图封顶会让封顶规则反过来吃掉目的**。

## 一 · 判据的宪法：Ω + A0 + T1
### Ω · 判别力（元公理 · LΩ）——一切判据的判据
一条断言是判据 ⟺ **它能排除一个世界**。
- 能答出「它排除的是哪两个世界」⇒ V > 0 ⇒ 属于判据；
- 答不出 ⇒ **仅为装饰，禁止写入文档**。

度量公式：
$$V(a; A_{good}, B_{bad}) = \log_2 \Big[ \frac{P(通过|A)}{P(通过|B)} \Big]$$

三处重要修正必须写明：
1. **V 以世界对为参数**：同一判据更换一组对比世界，V 值随之改变（P0b/P0d 正交可由此推导，不依赖直觉）；
2. **本领域 V 存在退化**：确定性场景下 P 仅取 0/1，V ∈ {0, +∞, −∞}；它只代表「能否区分」的布尔判断，**不是**用于比较判据强弱的分级度量；
3. **极性规则**：V > 0 ⟹ 具备可红能力；能红 ⇏ V > 0（两世界内均 50% 概率飘红，属于能红但 V=0）。极性由 $A_{good}/B_{bad}$ 固定，不看 |V|。

Ω 的第一个推论：**替换同义词不会改变两个世界的可分性 ⇒ V = 0 ⇒ 属于无效工作**
> 这就是「用同义词解决同义撞车 = 循环论证」的底层机制解释。

> **Ω 的适用边界（v3.1 补）**：Ω 管辖「怎么知道对不对」，**不管辖「值不值得做」**。
> 目的、使命、意义天然 V = 0，见 §〇·五 的显式豁免。
> 用 Ω 去删意义，属于**范畴错误**——如同用"完备性"去判"命名公理不完备"（见 §三 公理完备性）。

### A0 · 以发生为单位记账（领域事实 · L0 · 自封起点）
系统统计的是**发生**，不是「想要执行」。
> 判据：身份是否按发生计数？（代码可判，命令待补充，登记 §七）

边界说明：**到达次数 ≠ 业务身份**
用户提交一次请求、客户端重试 N 次，物理上是 N 次到达；业务上计数由幂等键 / 请求 ID / 去重边界决定，不由 A0 决定。（N 仅作示例，非实测值）

### T1 · 可拒绝性（设计约定 · L0′ · 与 A0 平级自封，非推论）
- 尚未提交、可被拒绝或撤销：**意图**
- 已提交、不可改写的记录：**事实（事件）**

事件可通过后续事件**更正或补偿**，但历史原始记录本身不被覆盖。
二分分类，无第三类——**属于带作用域的约定，不是已证明穷尽的分类体系**。
> 判据：能否被拒绝？前置问题：它是不是变更单元？

Ω 检验：排除的世界对 = **已提交 / 未提交**；V > 0 ⇒ 属于判据。

> 为什么不是 A0 的推论（v12 定谳）：
> ① 按发生记账的系统完全可以拒绝请求；
> ② 不可改写的记录仍可被补偿事件改变业务效力。
> **伪造推导比承认约定更危险**——下游会误将约定当作定理使用。

#### 作用域判据（不是名单）
变更单元 ⇔ 对象写入操作进入事件流 / 必须经过 apply()
- ✅ 是 ⇒ 受 T1 约束
- ❌ 否 ⇒ 不受约束（声明 / 观测 / 触发源 / 投影）

示例（不受 T1 约束）：
配置声明 · 外部观测 · 定时触发（定时结果才是变更单元）·
校验失败（拒绝本身是事实）· 投影缓存

**已提交但副作用未完成**：属于作用域边界场景 ⇒ 需要 Outbox 机制，见 §五 P1。

> 作用域边界 ≠ 第三类
> 作用域边界代表：T1 对该项**不作主张**（在作用域之外）；
> "第三类"代表 T1 主张存在第三种事物。二者形式相似、本质相反。

**挂起意图不是第三态。**
挂起意图可被拒绝，这正是确认门的意义；它本质是队列中的一条意图。
它的持久化形态（`IntentProposed` 等，事件流里「一条意图被提出」的事件类型），是**关于意图的事实**，**不是意图本身**。
挂起队列由事件流重放派生，不需要单独持久化。

> 重放安全硬约束：未获重新确认的 pending intent，**不得因重放自动执行**
> 否则重放会静默执行人类从未批准的意图。

由此衍生核心流程：
```
意图(CI-144：第144号协议，意图统一表达格式) --apply（唯一入口）--> 事件
事件 --追加·max+1（编号 = 当前最大 + 1）--> 事件流
事件流 --重放--> 对象图 --派生--> 视图

删除不是撤销，是追加一条新事实（tombstone 墓碑 / purge 清除）
```

#### 结构断言：log 即是 store（设计主张，非推论）
事件溯源链「追加 → 重放 → 对象图 → 视图」的结构主张：**log 本身就是事件源，不存在第二个独立 store**。
两点用途：
1. 作为 **WAL（预写日志）**判决的 A3b 依据：WAL 自带断言「日志守护另一个 store」，与本主张相反 → 判定为假，因此重命名为「事件流」；
2. 作为视图层的借势依据：断言「只读、由源派生、自身不存储数据」成立，借势生效。

**核心思路：把不可判定的「想到什么」，替换成可核验的「断言核对」。**

### 裁决层级（冲突时自上而下）
```
LΩ Ω 检验 → L0 公理否决（A0 / T1）→ L2 A2–A5 命名规则 → L3 C 组图校验 → L4 代码
```
> **代码 = 证据方 + 平局裁决方，无否决权。**
> 代码可能反映旧实现与历史债务；若把代码当作唯一来源，架构语言会被当前实现锁死。
> 平局裁决资格本身必须通过 Ω 检验：代码侧判据在对应世界对上 V > 0，才有裁决权；否则交由定义侧。
>
>「代码为准」仅在上层规则未否决时生效；**代码胜 ≠ 问题已解决**，必须记入迁移债表（§三）。

## 二 · 概念地图：四层 + 一条进程轴（29 张卡，卡片口径）
四层回答「这层是什么」，进程轴回答「代码跑在哪」——**两个独立维度，不是第五层**。

**维度三规则**：逻辑职责（这层是什么）· 部署位置（代码跑在哪）· 横切机制（贯穿多层的约束）
三维分开判断；跨维度双属主**不算**占用两层（C2 仅禁止**同维度内**重复）。

层间关系：
1. 契约层：给 ②③④ 提供共同语言（横切视角，不强制单向依赖）；
2. 事实层：唯一真相源；
3. 视图层：只读，派生自事实层；
4. 适配层：将外部世界翻译成契约层语言，送入事实层。

状态标记说明：● 现状（11）· ◐ 待更新（4）· ○ 新（14）

### ① 契约层 · 大家怎么对话（5）· 横切
- ● **CI-144 意图**：统一行动语言。代码 `Ci144Intent`，限定并入词本身（G0①）。
  A3b 四字段已落纸：采用义「CI-144 协议定义的行动单元」· 来源语境「本文档协议族」·
  对应架构属性「统一行动语言」· 为何他义不适用「Android Intent 是组件间消息对象，不同域」。
  **结论：加限定后歧义可接受**（不是「无冲突」）
- ● **Helix-Mind 语义契约**：契约本身；产物「语义快照」归属 ③（A5 拆分，不跨层占用）
- ● **事件流契约**：写入**规则**本身——append（只许追加）· max+1（编号分配）·
  尾换行 · 半行拒绝（防脏数据）。**规则，不是数据**（与下方事件流卡片可分，L26 近名检查）
- ● **运行模式**：drive / partner / survive。**声明语义 ⇒ 不是状态 ⇒ 归契约层**（G0②）；
  「切换」不进入意图动词表——不存在的操作不给名字（A4）。**本卡归属由声明语义独立得出，
  不依赖字段可选性**（config.rs 行号与字段状态待 G1 核验，真伪由判据裁决）
- ○ **段自带序号**：消除「第 i 个 turn/start ↔ win.jobs[i]」隐式下标对齐（A5）

### ② 事实层 · 什么是真的（10）
- ● **事件流**：按事件流契约落盘的事件集合——**数据，不是规则**
  （原错误名称：「Intent 日志 / WAL」）
- ● **对象图**：支持分叉，是 DAG（有向无环图）不是树（原错名「状态树」）
- ◐ **意图入口 apply**：**设计目标——唯一必经入口**；现状仍存在绕过调用点；
  CI-144 意图格式待 M5 适配器 ADR 接入（G1① 判定泄漏面；P0c 棘轮计数不增）
- ● **删除三旋钮**：D0 墓碑（软删除）/ D1 回收+purge / D2 销毁保 id（编号永不复用）
- ● **生命周期**：腾位 / 宽限 / 持有者（声明式 owner，重启可识别，孤儿具名）
- ● **refs 三层**：指针存储在仓库、重启持久；客户端以服务器为准
  （指针属于数据、属于事实，不属于部署拓扑——因此归入本层）
- ○ **复活**：重放事件流重建状态，重放即审计（重放属于事实层操作）
- ○ **交互模式**：normal / pane / tab / locked，**可切换**
  > 与运行模式分工：运行模式 = 声明（不可切换）；交互模式 = 状态（可切换）（G0②）
- ○ **确认门**：高风险意图挂起待批；**目标失效 ⇒ 标记 stale ⇒ 降级需重新确认**
  （G0③：意图携带目标 ref，apply() 核对存活；类比 GitHub 合并前查分支、交易成交前查账户）；
  **外部存活检查是 apply 时实时前置条件，不是重放产物**
- ○ **项目注册表**：Agent 的项目寻址空间；当前仅增加字段（零成本），P3 落地实现

## 三 · 命名纪律（干）
元原则：**领域定义提候选，代码给证据，公理来否决。**
三阶段流程：
1. **领域定义提出候选词**：先明确概念、边界（可借用业界术语）；
2. **代码提供映射证据**：优先复用代码已有词汇（`event_family` ⇒ 事件）；代码不存在则从现有词汇派生；
3. **全部候选必须经过 A2–A5 校验**。未被否决即为最终名称。

> 并列原则（不替换元原则）：V > 0 在哪，真相就在哪。
> 元原则定义**谁拥有命名权**；Ω 判断**判据是否具备证据力**，二者不可互相替代。

冲突执行顺序（三段）：
1. 公理否决（A2–A5，最高优先级）；
2. 定义与代码冲突 ⇒ **代码胜**（平局裁决方，保障迭代推进）；
3. **必须记入迁移债表**：当前代码名 ≠ 目标架构名，列为待迁移项。
> **代码胜 ≠ 问题已解决。**

### A2–A5 五条命名规则（均为 Ω 的实例）
| 规则 | 一句话 | Ω 世界对 | 判据 |
|---|---|---|---|
| A2 机制 ≠ 内容 | 桶是桶，桶里的东西是桶里的东西 | 容器 / 内容 | 它是桶，还是桶里的东西？ |
| A3a 仓库内 | 本仓库无同名占用 | 同物 / 异物 | grep 出来是不是同一个东西？ |
| A3b 跨语境 | 名字的结构断言为真 | 断言真 / 断言假 | 断言写出来（落纸），它对吗？ |
| A4 具象性 | 词能指认到代码或说清职责边界 | 这段代码 / 那段代码 | 能指出来，或说清边界吗？ |
| A5 一物一名 | 禁止第二份清单 | 一词一物 / 一词两物 | 反查唯一吗？ |

- **A4 两条要求**：
  ① 代码映射：可映射到模块 / 类型 / 接口 / 代码区域（**不必是单独一行**）；
  ② 架构定义：职责边界清晰，即使无单一代码位置（契约层、进程轴属于此类）。
  顺序：先 A2（语义分层），再 A4②（职责边界）；冲突以 A2 为准——A2 管控语义，A4②仅管控表达。
- **A3b 是可审议的语义核对，不是客观判定器**：依赖词义选取与语境。
  外借术语必须落纸**四字段**：采用义 · 来源语境 · 对应架构属性 · 为何其他常见义不适用
  （当前唯一完整样例：WAL，判例 #10；其余待补）。
- **A3 拆分为两条的原因**：grep 检索不到 WAL（仓库无此实体）；WAL 的否决依据是跨语境结构断言。A3a 管仓库内（grep 可自动判定）；A3b 管结构断言（书面人工核对）。
