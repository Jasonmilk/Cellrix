# ADR-0045: 健康探针必须看得见状态行 —— 看不见 404 的探针不是探针

- **状态**: Proposed（待人类批准）
- **日期**: 2026-09-24
- **决策范围**: Cellrix 的 HTTP 传输层（`web/src/http.rs`）与所有以 `probe()` 为健康判据的调用方（`up`、面板的生态探测）
- **关联**: `DNA` 原则 11（零硬编码 · 单一来源）、`RNA` 通用铁律 9（非空转自证）；跨仓：`Tuck:ADR-0004`（内容治理网关 · 唯一门）、本 ADR 的判据是 `Tuck:ADR-0006`（审计链必须配置且可验证）能否成立的前提
- **引用约定**: ADR 编号按仓内序号递增；跨仓引用必须带仓名（见 `ADR-0022` 文首）

---

## 1. 背景

### 1.1 探针读的是正文，不是状态行

`web/src/http.rs` 的手写 HTTP 客户端**从不解析状态行**：

```rust
buf.split("\r\n\r\n").nth(1)              // plain_request，:51-54
  .map(|s| s.to_string())
  .ok_or_else(|| "empty response".to_string())
```

```rust
pub fn probe(base: &str, path: &str, bearer: Option<&str>) -> Result<(), String> {
    let body = fetch_json(base, path, bearer)?;
    if body.trim_start().starts_with('{') { Ok(()) } else { Err("unexpected body".to_string()) }
}                                          // :60-67
```

⇒ 判据只有两条：**连得上** + **正文以 `{` 开头**。**状态码不参与判断。**

### 1.2 实测：一个 404 被读成「运行健康」

审查当日实测（本机，`Tuck` 真进程）：

```
启动日志  "content-governance gateway serving" … "audit":""
GET http://127.0.0.1:60052/v1/audit?limit=1
      → HTTP 404 {"error":{"message":"audit chain not configured","type":"no_audit_chain"}}
GET http://127.0.0.1:60052/v1/stats → HTTP 404
```

该 404 的正文**以 `{` 开头** ⇒ `probe()` 返回 **Ok**。于是：

- `up` 的 Tuck 健康检查走的正是 `/v1/audit?limit=1`（`web/src/bin/up.rs:538`），它在 Tuck **审计链未配置**时打印 **「Tuck: ✅ 运行中」**。
- 面板的生态探测同样以此为准。

⇒ **审计腿整条是死的，而所有绿灯都亮着。** 这正是 `RNA` 铁律 9 要治的形状：判据在场，但它抓不住它声称要抓的东西。

### 1.3 为什么这件事排在链路工作最前面

链路接线（记忆腿 / 执行腿 / 审计腿）的每一步验证**都以探针说真话为前提**。在探针看不见 404 之前，任何「已就绪」的结论都不可信——包括本 ADR 后续几支自己的验收。故先修判据层，再接线。

---

## 2. 决策

1. **`plain_request` 保留状态行。** 新增 `plain_request_status()` 返回 `(u16, String)`；`plain_request()` 退化为它的正文投影，**既有调用方的返回契约不变**（面板代理仍要能读到服务端自己的错误正文，那是有价值的）。
2. **状态行解析失败 = 失败。** 读不到状态行（畸形响应 / 半开连接）时返回 `Err`，不得当作成功。默认 fail-closed。
3. **`probe()` 要求 2xx。** 判据变为「**2xx** 且正文以 `{` 开头」。非 2xx 时 `Err` 里带上状态码（`HTTP 404`），让调用方与日志能说出**哪一层**不健康。
4. **状态码只增不减地可见。** 代理路径继续把服务端正文透传给消费者；本 ADR 只让 `probe()` 多知道一件事。

---

## 3. 理由

- **物理事实优先**：HTTP 状态行是协议里**唯一**被设计来表达「这次请求成功了没有」的字段。绕开它去猜正文形状，等于用代理指标替换物理事实。
- **单一职责**：「连得上」与「这个器官健康」是两件事。`probe()` 是后者，所以它必须读那个表达后者的字段。
- **不发明新概念**：不做重试、不做语义化状态映射、不引入 HTTP 库。只解析已经在线路上的一个 token（`零硬编码` / `极简依赖`）。
- **代价可忽略**：一次 `split_whitespace().nth(1).parse::<u16>()`，无分配新增（`节能`）。

---

## 4. 不做什么（Non-Goals）

- **不**把 `fetch_json` 改成非 2xx 即 `Err`。面板的驾驶舱/证轨需要把服务端的错误正文显示给人看；把正文丢掉换来一个泛化的 Err 是退步。
- **不**引入重试、退避、熔断。可达性语义不变。
- **不**改流式（SSE）路径与 POST 路径的语义。
- **不**在探针里做 JSON 解析。形状检查保持「以 `{` 开头」这一条廉价判据，只把**状态码**加进合取。

---

## 5. 影响

- **正向**：`up` 与面板的绿灯重新有意义。`Tuck` 审计链未配置时，`up` 会如实报告不健康——这是发现 `Tuck:ADR-0006` 那个缺口的前提。
- **代价**：任何**依赖旧行为**（404 也算健康）的调用方会立刻变红。这是**有意的**：那些绿灯本来就是假的。已核对的调用方：`up` 的 Tuck 检查（`/v1/audit?limit=1`）、`up` 的 Anaphase 检查（`/v1/health`，200）、面板的生态探测。
- **风险**：某些服务可能用 3xx 表达「正常但搬家了」。本仓链路上没有这样的端点（全部 loopback、无重定向）；若将来出现，应在该端点自己的 ADR 里处理，而不是让探针整体放宽。

---

## 6. 验收（判据必须能红 —— 铁律 9）

判据：`web/src/http.rs` 的单元测试，用一个**测试内 TCP 监听器**返回构造好的响应，**不用真服务**（判据不得依赖第三方可用性）：

| # | 合成输入 | 期望 |
|---|---|---|
| 1 | `HTTP/1.1 404 Not Found` + `{"error":…}` | `probe()` **Err**，且消息含 `404` |
| 2 | `HTTP/1.1 200 OK` + `{}` | `probe()` **Ok**（阴性对照：不得过宽） |
| 3 | `HTTP/1.1 200 OK` + `not json` | `probe()` Err（原有形状判据仍在） |
| 4 | `HTTP/1.1 500 …` + `{}` | `probe()` Err |
| 5 | 畸形响应（无状态行） | `probe()` Err（fail-closed） |

**变异注入（两侧都要做）**：

- 把 `probe()` 的状态检查去掉（还原成改动前）⇒ **#1 / #4 必红**；还原 ⇒ 必须转绿。
- 把形状检查去掉（只要有状态行就 Ok）⇒ **#3 必红**；还原 ⇒ 转绿。

两条都做，才能同时排除「永远红」与「永远绿」的坏判据（铁律 9 的「两侧都要做」）。

### 6.1 实测记录（2026-09-24，本机）

| 步骤 | 结果 |
|---|---|
| 改动后 `cargo test -p cellrix-web --lib http::tests` | **8 passed / 0 failed** |
| 连续 10 次重跑 | **10/10 绿**（不抖） |
| 变异 1：`if !(200..300).contains(&status)` → `if false` | `probe_errs_on_404_with_a_json_body`、`probe_errs_on_500_with_a_json_body` **变红**；还原 ⇒ 转绿 |
| 变异 2：`if body.trim_start().starts_with('{')` → `if true` | `probe_errs_on_2xx_that_is_not_our_json` **变红**；还原 ⇒ 转绿 |

### 6.2 顺带修掉的一处**判据抖动**（写这条判据时才暴露）

第一版测试用的合成对端**只写不读**：服务器不排空请求就关闭连接，内核因此发 **RST** 而不是 FIN，客户端的 `read_to_string` 会在**响应已送达**的情况下报 `ECONNRESET`。表现为：**并行跑必红、单跑必绿**。

⇒ 合成对端现在**先排空请求再回应**，并显式 `shutdown(Write)`。这同时修掉了既有 `probe_ok_on_json_and_err_on_garbage` 里同样的潜在抖动（该用例已被本 ADR 的正/负两个对照覆盖，故合并删除，不减少覆盖）。

**记录它的理由**：一条会抖的判据比没有判据更糟——它教人重跑，而不是去查因。

---

## 7. 与链路工作的关系

本 ADR 是链路闭环的**判据层**。它单独不接通任何一条腿，但：

- 不修它 ⇒ `Tuck:ADR-0006`（审计链配置）的验收无法成立；
- 不修它 ⇒ 记忆腿/执行腿的「已就绪」无法与「Noop 静默降级」区分。

⇒ **顺序硬约束：本 ADR 必须先于本轮的链路接线改动合入。**
