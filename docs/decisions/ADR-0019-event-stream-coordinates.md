## 🔴 覆盖事故：能定性了 —— 被写进去的是**回复正文**

两次被覆盖内容的首行：

| 次 | 首行                          | 出处            |
| - | --------------------------- | ------------- |
| 1 | 「直接回答：一半该…」                 | 我回复的开头        |
| 2 | 「审查完毕。**D0b 是一份高质量的负面结果…**」 | 我**上一轮**回复的开头 |

⇒ 写进文件的**不是任何生成物，而是回复文本本身**。某个环节把"AI 回复"当成了"文件内容"——你那边若有并行会话在用别的助手，它很可能把回复整段重定向进了 ADR。

**光靠"记得提交"防不住第三次，需要结构性闸门：**

```
# 全局找其他被污染的文件
grep -rl "审查完毕\|直接回答\|^# 审查结论" --include=*.md /Users/jason/Doubao/chats/Jasonmilk/ 2>/dev/null

# pre-commit 钩子：ADR 首行必须合规
for f in $(git diff --cached --name-only -- 'docs/decisions/*.md'); do
  head -1 "$f" | grep -qE '^ADR-[0-9]{4}:' || { echo "REJECT: $f 首行不是 ADR 头"; exit 1; }
done
```

第二条和 ADR-0018 §6c「占位符清单一一对应」是**同一思路**：把文档完整性变成可执行断言，而不是靠人记得看。
