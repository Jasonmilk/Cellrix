# ADR-0019: 事件流坐标与通道身份

- **状态**: **Proposed**（含**三个决策点**：D0 粒度三选一 / TBD① / TBD②，待裁决）
- **日期**: 2026-09-15
- **关联**: `Cellrix:ADR-0018`（事件族装配层 —— 本 ADR 细化其 D3 / D5 / D7 的坐标语义）、
  `anaphase:ADR-0026`（会话事件流 —— `seq` 语义的持有者）、
  `docs/DNA.md` 原则 7（物理事实优先）/ 原则 11（0 硬编码）
- **取代**: 无

> **跨仓引用一律仓名限定**：`Cellrix:ADR-0018` ≠ `anaphase:ADR-0018`。

## 1. 背景与问题

**一个 `seq` 同时承担两份职责**：

| 职责 | 现状落点 |
|---|---|
| **turn 内唯一性**（幂等去重键） | `bySeq[e.seq]` |
| **跨 turn 排序**（tape 顺序、水位线） | `comparePosition` / `watermark` |

而 `seq` 的实际语义是**turn 内局部**的 —— `anaphase:ADR-0026` D2 原文即
`seq — monotonic within a period`。

**实测（2026-09-15，86 个真实 period / 753 个事件）**：

```
run-7efbf0f8（55 行）: seq = 0..10, 0..10, 0..10, 0..10, 0..10   ← 5 轮
run-3d262481（35 行）: seq = 0,1,2,3,4 ×7                        ← 7 轮
```

⇒ **一个事件文件 = 一个 job = 多个 turn**，每个 turn 的 `seq` **从 0 重开**。

**后果**：装配层按全局 `seq` 去重 ⇒ **第 2 个 turn 起的事件全部被拒**
（实测：8 个事件只进 4 个，第二个 turn 全部 `duplicate`）⇒
面板表现为「第二问之后记录消失」。

**这不是实现 bug，是坐标缺失** —— 把两个不同职责压在同一个标量上。

## 2. 决策

### D0｜**前置问题**：period 与 job 的粒度关系（先于 TBD①）

本 ADR 初稿把「`seq` 每 turn 重开」当作**给定约束**去适配。**这是错的顺序** ——
必须先问这个约束**本身是不是缺陷**。

**契约原文**（`anaphase:ADR-0026` D2）：`seq — monotonic within a period`。
而实测：每 turn 从 0 重开。⇒ 关键在 **period 与 job 是什么关系**。

**代码取证（2026-09-15，`anaphase-helix`）**：

| 位置 | 事实 | 指向 |
|---|---|---|
| `run_cycle.rs:931` | `SessionEventStream::open(...)` 在 **`turn/start` 时**调用；注释原文「open the **per-period** stream and emit the **period header** — turn/start」 | **period = turn**（意图） |
| `session_events.rs:113` | `open(dir, job_id, ...)` 生成 **`{job_id}.events.jsonl`**，且注释写「**One period = one event file**」 | **文件按 job 键**（实现） |
| 实测 `run-7efbf0f8` | **5 轮同文件**，5 轮输入**完全相同**（同 `derive_job_id`）⇒ 同 job_id ⇒ 同文件；`seq` 每轮重开 | **粒度不一致的产物** |

⇒ **既不是「设计如此」也不是「anaphase 计数器写错」**：
**意图说 period，文件名说 job，两者不一致。**

**⇒ TBD① 的问法必须升级**（本 ADR 的核心修正）：

> 不是「服务端要不要带 turn」，而是
> **「period 与 job 的粒度关系是什么」** ——
> ① period = turn（则文件名须含 turn，`{job}-{turn}.jsonl`）
> ② period = job（则 `seq` 应 job 内单调，需修 anaphase 计数器）
> ③ 保留「一个 job 一个文件、内含多 turn」（则**显式承认**，并把 turn 作为通道身份写进协议）

**D0 已不阻塞（2026-09-16）** —— I3 的 `jobId#gseq` 带 job 作用域前缀，
**D0 三种粒度下 `gseq` 都安全**。原文「裁决前不落 seq 修复」已不成立：

> **未决（取证未尽，不猜）**：`open()` 用 `truncate(true)`，按理每次只留最后一轮；
> 但实测一个文件有 5 轮。**两事实矛盾**，我未能从代码调和 ⇒ **记录为未决**，
> 需在裁决前单独查清（可能涉及多次进程运行或另一条写入路径；
> `main.rs:591` 的 `append(true)` 经查写的是 `agent.events`（`StageEvent`，另一事件族），
> **不是**同一文件）。

### D1｜两个坐标分工

| 坐标 | 语义 | 来源 | 用途 |
|---|---|---|---|
| **`gseq`** | **全局位置**（= `global_position`） | **读取边界按行序赋予** | **主键**：身份 + 全序 + node id |
| **`seq`** | **turn 内**位置，从 0 重开 | 生产者（**现状不变**） | turn 内唯一性 + 乐观并发 |
| **`turn`** | 轮次序数 | 同一边界派生 | **仅显示分组，不进 node id** |

**`gseq` 是主键**（2026-09-16 定稿，推翻初稿的「可能冗余」）：

- **来源写死**：**读取边界按行序赋予**，**不得**从 tape 状态推导 ——
  否则验收条 4 的「补更早分页」会直接破坏它。
- **身份与分组分离**：**身份 + 全序用 `gseq`**，**显示分组用 `turn`**。
  `turn` 序数**不得**进入 node id。
  ⇒ 上一轮「验收条 4 无法稳定」的结论**由此推翻**：错在**把 turn 塞进了身份**，
  而不是身份本身不可稳定。实测已证：`gseq` 模式下三套全绿，且变异测试两个变异
  都能让断言转红（负向证据齐备）。

**⚠️ `gseq` 是「读取边界的行序」，不是「文件行号」**（易混，2026-09-16 指出）：

消费方（`session.html`）拿到的是 **API 返回的数组**，赋的是**数组下标**。
两者相等的**唯一保证**是「API 返回顺序 == 文件行序」，而它当前只靠
`read_period` 的 `fs::read_to_string` 这个**实现细节**成立。
⇒ 见 I1 与 normalize 内的**连续性守卫**。

**为什么叫 `turn` 而不叫 `channel`**：结构上二者等价 —— `BIND-19` 的
`Channel ID` + `Sequence ID`（per-channel 单调）正是同一分工的先例。
**但语义不同**：`BIND-19` 的通道是「256 路**并发复用**」，而 turn 是**顺序**的。
借它的**结构**，不借它的**名字** —— 否则会让人误以为 turn 可并发。

**`seq` 的现有语义明确不变** —— 不动生产者，也**禁止**「顺手把 seq 改成全局」：
那会绕过 D2，把通道身份重新变成**消费者数出来的事实**。

**落地范围（spike 实测：4 处 + 1 个 helper）** —— `posOf(e) = typeof e.gseq === 'number' ? e.gseq : e.seq`：
水位线读取、`digest` 的 `wm`、`deriveCoordinates` 的 `node` id、
`countsUpTo` 的 turn 序数、`comparePosition`。

**其中「快速路径」与 `comparePosition` 必须同时改**：若只改后者，下一轮事件会走
快速路径被**推到尾部** —— **数据全在、全部错序、无任何计数变红**。
为消除这个风险，快速路径**改为经由 `comparePosition` 调用**，
使「只有一处比较逻辑」成为**事实**而非意图。

**范围声明（2026-09-16 更新）**：`watermark` **已改为 `posOf(e)`**（spike 已验证），
即**它已随 `gseq` 一起处理**。前提是 `gseq` 已在上游赋好（见 I1/I2）。
`watermark` **仍是标量 `seq`**，其**表示**尚未处理 ——
不要读作「watermark 也已经好了」。

### D2｜通道身份由**生产者**给定

判据（成熟实践）：**流 = 需要独立并发控制与独立重放的最小单位**；
而**通道身份由业务/生产者给定**，从不由消费者数出来。

本场景：`seq` 在每个 turn 内重开 ⇒ **turn 就是流**。

> **TBD①（2026-09-16 降级：鲁棒性，非阻塞）**
>
> **降级理由**：`gseq` 在**读取边界**赋值，对**新文件与旧文件一视同仁** ——
> 生产者带不带 `turn`/`span-id`，消费方的归一化路径都不变。
> ⇒ 跨仓请求**不是正确性前提**，**不阻塞任何东西**。
> **但它仍有真实价值**（2026-09-16 指出，比原措辞更有说服力）：
> **让「API 返回顺序 == 文件顺序」变得可被检测** ——
> 生产者给了 `gseq`，数组顺序一错就能立刻发现；只靠数组下标，**永远发现不了**（见 I1a）。
> 原重述（"不是人情，是既有义务"）仍然成立，只是**优先级从阻塞降为增强**。
>
> **TBD①（2026-09-15 原重述：这不是人情，是既有义务）**
>
> 原措辞是「请 `anaphase` 在事件里带 turn」，读起来像跨仓请求。**但它不是。**
>
> `CommonIntents-144` 声称「**每一笔事务**都可通过 W3C Trace Context 完全追溯」，
> 而**会话事件流就是这套系统的审计载体** —— 它记录的每个 turn 就是一笔事务。
> ⇒ **事件流不带 trace/span 上下文，CI-144 的可追溯性声称在它自己的审计载体上是断的。**
>
> ⇒ 应重述为：**`anaphase` 在自家宪法下已负有 trace context 义务，
> 会话事件流是唯一还没履行它的地方。**
>
> **字段名不必发明**：`turn` ≈ span-id、`job_id` ≈ trace-id，
> 均为工业标准形态（`traceparent` 的两级身份）。
>
> **裁决前**装配层只能派生 turn 序数，而派生**不满足本层自己的不变式**（见下方「负面结果」）。

### D0b｜**负面结果**：在 `accept()` **内部**派生 turn 索引不成立（已实测）

一次尝试（2026-09-15 晚，已回滚）在 `accept()` 中按 `turn/start` 计数派生 turn 索引，
并让 key = `(turn, seq)`。**结果：MULTI-TURN 三条转绿，但同时打破 4 条既有验收条。**

| 冲突 | 现象 |
|---|---|
| **分块不变性**（验收 10） | 要求 turn 索引**跨 `feed` 累加** |
| **补更早分页**（验收 4） | 要求 turn 索引**能回退重算**（早到的 `turn/start` 会把后续编号整体推位） |

**实验的边界必须写清**：喂入的是**原始事件**（`feed(shuffled)` / `feed(后半段)`）。
⇒ 它证明的是「**派生不能发生在 `feed` 内部**」，**不是「派生不可能」**。
它**从未覆盖**「派生发生在 `feed` **之前**、由**看到完整流**的归一化层赋予」这条路。

**两条路的边界（已算清）**：

| 断言 | 归一化层（feed 之前派生）能否解决 |
|---|---|
| MULTI-TURN 零拒收 / 全进 tape / node 唯一 | ✅ 归一化后 `(turn, seq)` 唯一 |
| 分块不变性（验收 10） | ✅ turn 已是数据，按位置排序，与喂入顺序无关 |
| coordinates ignore arrival order | ✅ 同上 |
| **补更早分页（验收 4）** | ❌ **在 turn 进 node id 的前提下** |

⇒ 该 ❌ 的**原因是 node id 含 turn 序数**。**改用 `gseq` 后转为 ✅**（见 D1）：
`gseq` 在**分块之前**已固化，先喂后半段、再补前半段，既有 `jobId#gseq` **不变**。
⇒ **本行结论由 D1 取代**；此处保留，是因为**错在过度概括，不在实验本身**。
（span-id），不是序号。

⇒ **结论（修正）**：

- **TBD① 仅阻塞验收条 4** —— 它**不阻塞 A1/A2**。
- **A1/A2（即用户症状「第二问之后记录消失」）由归一化层今天即可解锁。**
- **验收条 4 状态 = 暂不支持（可恢复）**；
  **恢复条件**：turn 成为生产者给定的稳定身份（见 TBD①）。

**未验证项（不得当作已解决）**：后续改用 key = `(seq, time)` 曾让幂等通过，
但 `time` 是**注入时钟字符串**，同一 turn 内 `tool/call` → `tool/result` 的间隔
**可能低于时钟分辨率** ⇒ **两个不同事件可能得到同一 key ⇒ 幂等会误杀**。
⇒ 记为**未验证**；采用前须实测 86 个文件里 `(seq, time)` 的重复数。

### D3｜防呆的实现方式

**实测**：事件的**顶层 `job_id` 出现 0 / 753 次** ⇒ 事件**不携带**身份字段。

⇒ 原方案「`feed()` 校验事件 job_id 与 tape 绑定一致」**在当前数据下无法实现**。
两条路：

- **a**：`feed(events, periodId)` **显式传**，不等则整批拒 —— 调用点手边即有身份
- **c**：`anaphase` 在每个事件里带 `job_id` —— 跨仓，与 TBD① 同批

> **TBD②**：走 a 还是 c。

### D4｜`Cellrix:ADR-0018` D7 的 `gaps` 语义修正

原文写 `watermark = { lastSeq, gaps }`。**修正为两个被明确分开的概念**：

- **`watermark`** = **进度断言**（「我确定到哪儿了」）
- **`gaps`** = **已知缺失的呈现**，**不触发任何动作**

**理由**：整个 job 文件**已全在手**，不存在「还没收到」⇒ **「回拉补齐」无从谈起**
（那是**流式消费者**的概念，本场景不可能实现）。
D7 的 `gaps` 是**呈现层事实**，用于**诚实展示**，不用于触发。

### D5｜fold 必须是 **monoid**

验收条 9/10 的数学表述 —— **结合律 + 单位元 + 幂等**：

```
feed(a + b) == feed(feed(a) + b)     // 结合律
feed([])     == 单位元                // 单位元
feed(a + a)  == feed(a)              // 幂等
```

**一句话统摄 9/10**，并给出**约束**：tape 的排序**必须跨 turn 确定** ——
否则 `feed(a+b) != feed(b+a)`，**结合律破**。

**这正是当前 `comparePosition` 单键 `seq` 的缺陷**：跨 turn 顺序不确定。

**与验收条 4 的冲突**：若 turn 由**派生**得到，补更早分页 ⇒ turn 序号整体 +1
⇒ **既有 node id 全部变化** ⇒ 破「数据未变的既有 keyed node 值不被替换」。
⇒ ~~这构成 TBD① 的判据~~（**已由 D1 取代**：turn 不进身份 ⇒ 该冲突消失）
**已选：两者都不需要** —— node id **不含 turn**（I3），身份用 `gseq`。
⇒ 既不必要求生产者给定 turn，也不必声明不支持补更早分页。**本段由 D1 取代。**

### D6｜诊断：失败分类与样本隐私

| 失败类型 | 响应 |
|---|---|
| **永久**（畸形、schema 不符） | 进诊断计数 |
| **幂等重复**（同流同 seq） | **观测，不进失败计数** —— 见下 |
| **跨 turn 碰撞**（不同 turn 同 seq） | **异常**，进诊断 |

**「静默」是错的，改为「分开记」**（初稿写「静默丢弃」，那是在制造**第三种静默** ——
正是本日修掉的 K13 与 `rejectSample` 同一个病）：

| 类别 | 落点 |
|---|---|
| 永久失败（畸形 / schema 不符） | `rejections()` ← **失败** |
| **幂等丢弃** | **`idempotentDrops()`** ← **观测，与失败分开** |
| 跨 turn 碰撞 | `rejections()` ← **失败** |

**分开才有意义**：幂等丢弃计数暴涨 ⇒ 上游在**重复投递** —— 这件事**必须能看见**，
只是不该与「畸形」混为一谈。

**关键**：只有 `gseq` 进键之后，「幂等重复」与「跨 turn 碰撞」才**可区分**。
⇒ **seq 修复是诊断计数可用的前提**，不是可选优化。

**样本隐私**：`rejections()` 默认**不返回 `data`**（可能含用户原文），
需显式 `{ withData: true }`；保留时按具名常量截断。

## 4. 不变式

- **`EF.TYPES` 的值集 == `KNOWN_TYPES`** —— 别名表必须完整（**无 UI 语义**）
- **`PT.TYPES` ⊆ `KNOWN_TYPES`** —— 渲染表是**子集**（含 `track` ⇒ **不派生**，
  否则校验契约被 UI 需求绑架）
- **`snapshot.layerVersion` 与 `digest.contractVersion` 永不比较** —— 回答不同问题

**坐标与归一化的不变式**（2026-09-16，随 `gseq` 定稿）：

- **I1｜完整有序流**：消费方必须在**分块之前**读到**完整且有序**的事件流。
  当前由 `read_period` 的 `fs::read_to_string` 保证 ——
  但**那是实现细节，没有断言保护**；将来谁引入真分页，本方案**静默失效**。
  ⇒ **必须写成契约并由断言守着**（见 I1a）。
- **I1a｜连续性守卫**：`gseq` 序列必须是 **`0..n-1` 严格连续**；不连续 ⇒
  **落诊断，不静默**（可捕获**丢行 / 重复行 / 截断**）。
  注：它**检测不到整体乱序**（真乱序时下标仍连续）—— 那正是 TBD① 的价值所在：
  生产者给了 `gseq`，数组顺序一错就能立刻发现；只靠下标，**永远发现不了**。
- **I2｜`gseq` = 过滤前的物理行号**：被丢弃的行**保留空位**，后续行**不得**前移。
  反了就会整体位移。
- **I3｜node id = `jobId#gseq`**，**不得含 `turn`** ——
  `turn` 是**显示分组**，不是身份。

## 5. 放弃了什么

- **放弃「一个 `seq` 走天下」的简单** —— 换来两个坐标各司其职。
- **放弃「装配层自己数 turn」** —— 派生看似省事，但与验收条 4 冲突
**身份由读取边界给定**（`gseq`，I2），**不需要生产者配合** —— 见 D1 与 TBD① 的降级。

## 附：identity 与 ord 分离（2026-09-16 实现，批次 1）

**问题**：`node = jobId#gseq` 把**身份**与**顺序**焊在一起。同一事件
**从 root 读是 `B#10`、从中间片读是 `B#0`** ⇒ **违反确定性**。

**裁决**：Node 上分列两个量，且各自不进对方：

| 字段 | 含义 | 是否进 id |
|---|---|---|
| **`node`** | **identity = `sourceJob#lineNo`** | ✅ **就是 id** |
| **`ord`** | **流内位置** | ❌ |
| **`lineNo`** | **所属文件内的行号** | 供导出 |
| **`source`** | **identity 的文件部件**（`sourceJob`，与 `lineNo` 并列） | 供分组与导出（2026-09-16 增订） |

**前置**：`lineNo` 必须在**合并之前**记下 —— 拼接会毁掉它
（`gseq` 是合并后的位置，随起点变化）。`normalize` 赋 `lineNo` = 本次流的行号；
`mergeChain` 拼接后用真实行号覆盖。**三者都必要**：
`gseq` 随起点移动 ／ `seq` 每轮重开 ／ **只有 `lineNo` 能做 identity**。

**⚠️ 有效期**：**identity 仅在「同一次读取 / 同一 digest」下有效**。
同输入重发 ⇒ 同 `job_id` + 文件 **truncate** ⇒ `B#3` 可指向重写后的另一条事件。
**digest 变化 ⇒ 整段重建，不按 id 打补丁。**

**验收**：同一事件**从不同起点读取 ⇒ 同一 id**（断言在 `assembly_test.js`）。
