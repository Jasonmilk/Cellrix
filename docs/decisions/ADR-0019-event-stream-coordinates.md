# ADR-0019: 事件流坐标与流身份

- **状态**: **Proposed**（含两个显式 TBD，待裁决）
- **日期**: 2026-09-15
- **关联**: `Cellrix:ADR-0018`（事件族装配层 —— 本 ADR 细化其 D3 / D5 / D7 的坐标语义）、
  `anaphase:ADR-0026`（会话事件流 —— `seq` 语义的持有者）、
  `docs/DNA.md` 原则 7（物理事实优先）/ 原则 11（0 硬编码）
- **取代**: 无

> **跨仓引用一律仓名限定**：`Cellrix:ADR-0018` ≠ `anaphase:ADR-0018`。

## 1. 背景与问题

**一个 `seq` 同时承担两份职责**：

| 职责 | 现状落点 |
|---|---|
| **流内唯一性**（幂等去重键） | `bySeq[e.seq]` |
| **跨流排序**（tape 顺序、水位线） | `comparePosition` / `watermark` |

而 `seq` 的实际语义是**流内局部**的 —— `anaphase:ADR-0026` D2 原文即
`seq — monotonic within a period`。

**实测（2026-09-15，86 个真实 period / 753 个事件）**：

```
run-7efbf0f8（55 行）: seq = 0..10, 0..10, 0..10, 0..10, 0..10   ← 5 轮
run-3d262481（35 行）: seq = 0,1,2,3,4 ×7                        ← 7 轮
```

⇒ **一个事件文件 = 一个 job = 多个 turn**，每个 turn 的 `seq` **从 0 重开**。

**后果**：装配层按全局 `seq` 去重 ⇒ **第 2 个 turn 起的事件全部被拒**
（实测：8 个事件只进 4 个，第二个 turn 全部 `duplicate`）⇒
面板表现为「第二问之后记录消失」。

**这不是实现 bug，是坐标缺失** —— 把两个不同职责压在同一个标量上。

## 2. 决策

### D1｜两个坐标分工

| 坐标 | 语义 | 来源 | 用途 |
|---|---|---|---|
| **`stream_id`** | 流身份（本场景 = turn） | **生产者**（见 D2） | 分区键 |
| **`seq`** | **流内**位置，从 0 重开 | 生产者（**现状不变**） | 流内唯一性 + 乐观并发 |
| **`global_position`** | **跨流**位置（文件行序） | 消费者可派生 | 跨 turn 排序 |

**`seq` 的现有语义明确不变** —— 不动生产者，也**禁止**「顺手把 seq 改成全局」：
那会绕过 D2，把流身份重新变成**消费者数出来的事实**。

**落地范围（8 处，必须成对改）**：去重键、快速路径判定、水位线赋值、
水位线读取、`digest` 的 `wm`、`deriveCoordinates` 的 `node` id、
`countsUpTo` 的 turn 序数、`comparePosition`。

**其中「快速路径」与 `comparePosition` 必须同时改**：若只改后者，下一轮事件会走
快速路径被**推到尾部** —— **数据全在、全部错序、无任何计数变红**。
为消除这个风险，快速路径**改为经由 `comparePosition` 调用**，
使「只有一处比较逻辑」成为**事实**而非意图。

### D2｜流身份由**生产者**给定

判据（成熟实践）：**流 = 需要独立并发控制与独立重放的最小单位**；
而**流身份由业务/生产者给定**，从不由消费者数出来。

本场景：`seq` 在每个 turn 内重开 ⇒ **turn 就是流**。

> **TBD①**：`anaphase` 写入端是否在事件中携带 `turn` 序号？
> **跨仓** —— 需 `anaphase:ADR-0026` 配合。**裁决前**，装配层只能**派生** turn 序数，
> 而派生与验收条 4「补更早分页只增加更早的行」冲突（见 D5）。

### D3｜防呆的实现方式

**实测**：事件的**顶层 `job_id` 出现 0 / 753 次** ⇒ 事件**不携带**身份字段。

⇒ 原方案「`feed()` 校验事件 job_id 与 tape 绑定一致」**在当前数据下无法实现**。
两条路：

- **a**：`feed(events, periodId)` **显式传**，不等则整批拒 —— 调用点手边即有身份
- **c**：`anaphase` 在每个事件里带 `job_id` —— 跨仓，与 TBD① 同批

> **TBD②**：走 a 还是 c。

### D4｜`Cellrix:ADR-0018` D7 的 `gaps` 语义修正

原文写 `watermark = { lastSeq, gaps }`。**修正为两个被明确分开的概念**：

- **`watermark`** = **进度断言**（「我确定到哪儿了」）
- **`gaps`** = **已知缺失的呈现**，**不触发任何动作**

**理由**：整个 job 文件**已全在手**，不存在「还没收到」⇒ **「回拉补齐」无从谈起**
（那是**流式消费者**的概念，本场景不可能实现）。
D7 的 `gaps` 是**呈现层事实**，用于**诚实展示**，不用于触发。

### D5｜fold 必须是 **monoid**

验收条 9/10 的数学表述 —— **结合律 + 单位元 + 幂等**：

```
feed(a + b) == feed(feed(a) + b)     // 结合律
feed([])     == 单位元                // 单位元
feed(a + a)  == feed(a)              // 幂等
```

**一句话统摄 9/10**，并给出**约束**：tape 的排序**必须跨 turn 确定** ——
否则 `feed(a+b) != feed(b+a)`，**结合律破**。

**这正是当前 `comparePosition` 单键 `seq` 的缺陷**：跨 turn 顺序不确定。

**与验收条 4 的冲突**：若 turn 由**派生**得到，补更早分页 ⇒ turn 序号整体 +1
⇒ **既有 node id 全部变化** ⇒ 破「数据未变的既有 keyed node 值不被替换」。
⇒ **这构成 TBD① 的判据**：turn 必须由生产者给定，或本层**明确声明不支持补更早分页**
（二选一，不许两可）。

### D6｜诊断：失败分类与样本隐私

| 失败类型 | 响应 |
|---|---|
| **永久**（畸形、schema 不符） | 进诊断计数 |
| **幂等重复**（同流同 seq） | 静默丢弃，**不进诊断** |
| **跨流碰撞**（不同流同 seq） | **异常**，进诊断 |

**关键**：只有 `stream_id` 进键之后，「幂等重复」与「跨流碰撞」才**可区分**。
⇒ **seq 修复是诊断计数可用的前提**，不是可选优化。

**样本隐私**：`rejections()` 默认**不返回 `data`**（可能含用户原文），
需显式 `{ withData: true }`；保留时按具名常量截断。

## 3. 验收条（新增）

| # | 断言 | 状态 |
|---|---|---|
| **A1** | 双 turn（各自从 0 重开）**零拒收** | **RED**（待 TBD① 落） |
| **A2** | `node` id 跨 turn 唯一（`Set(nodes).size == 事件数`） | **RED** |
| **A3** | 单 period（真实形状）零拒收 | ✅ `f466fbf` |
| **A4** | 快速路径与 `comparePosition` 成对（结构性，见 D1） | ✅ `63cae92` |

**A1/A2 当前为红是刻意的** —— 红 = 待落修复未落。
**绿灯会让人以为多轮已经工作**，而实测是 8 个事件只进 4 个。

## 4. 不变式

- **`EF.TYPES` 的值集 == `KNOWN_TYPES`** —— 别名表必须完整（**无 UI 语义**）
- **`PT.TYPES` ⊆ `KNOWN_TYPES`** —— 渲染表是**子集**（含 `track` ⇒ **不派生**，
  否则校验契约被 UI 需求绑架）
- **`snapshot.layerVersion` 与 `digest.contractVersion` 永不比较** —— 回答不同问题

## 5. 放弃了什么

- **放弃「一个 `seq` 走天下」的简单** —— 换来两个坐标各司其职。
- **放弃「装配层自己数 turn」** —— 派生看似省事，但与验收条 4 冲突
  （补更早分页 ⇒ turn 序号整体位移 ⇒ 既有 node id 变化）。**身份必须由生产者给定。**
