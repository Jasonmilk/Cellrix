# ADR-0047: E2E 的密封性与对照不变量（先冻形状，再写代码）

- **状态**: Proposed
- **日期**: 2026-09-24
- **决策范围**: 回归网里那条端到端命令（`web/tests/e2e_chain.sh`、`chain_legs_test.js`）
  及其派生装置（新的 `chain-env`）
- **相关**: `CI-144` §4.2（不变量）/§5（Grease）/§13.3（断言必须指向被消费的对象）;
  `Cellrix:ADR-0046`（面板端口一处声明）; `anaphase:ADR-0046`（接线声明）
- **编号保留**: 本编号**与占用同一笔提交**完成（撞号已发生三次，最近一次是全局标识符 K-119）。

## 1. 问题（实测，2026-09-24）

这条 E2E 曾连续三次以"看起来在证明"的形态骗过我：

1. **判据把全部历史录像算进去** ⇒ `tool` 与 `text` **双双通过**，等于什么也没证明；
2. 加**时间窗**（`CHAIN_SINCE`）——时间窗本身是 flaky 源（时钟、耗时、跨天、残留）；
3. 加**内容匹配**（录像的 `user/message` 等于本次 prompt）——**这仍然只是侦探式控制**。

同时：`job_id` 是**输入的哈希**（内容寻址），所以**同一个 prompt 跑两次得到同一个 job_id**——
上一轮的录像因此能"满足"本轮判据。**内容寻址精确复现了本条要修的缺陷。**

⇒ 结论：**匹配（时间/内容）都可以漏；隔离不会。**

## 2. 决策

| # | 决策 |
|---|---|
| **D1** | **一个标识一种用途。** `job_id`（内容键：去重、缓存、可复现）**保留**；新增 `run_id`（每次运行**随机**，用于隔离与关联）。**不得从 `job_id` 派生 `run_id`** —— 那是一栏两义。 |
| **D2** | **隔离是构造出来的，不是匹配出来的。**（Bazel execroot 模型）每次运行分配**私有** events 目录（`<workspace>/.helix/events/<run_id>/`）,断言**只读本次运行的目录** ⇒ 上一轮的录像**在物理上不可读**。`CHAIN_SINCE` 随之退休。 |
| **D3** | **一份 manifest。** 新可执行体 `chain-env` 产出 **`resolved.json`**（端口 + env + 计数**全部在其中**）,`start-panel.sh` 与 `e2e_chain.sh` **只读它**、自身不含任何派生逻辑。该 manifest **同时充当"生效 manifest"**（进程自落的那一层）。 |
| **D4** | **manifest 必须确定性**（前置条件，见 §4）：无时间戳、**无绝对路径**（值保留 `<workspace>` 占位符，用时展开）、键**排序**、locale 固定、**只含白名单键**。 |
| **D5** | **结构性 tripwire**：两个 shell 脚本中**端点/端口字面量计数为 0**。 |
| **D6** | **静态对照**（每次跑，毫秒级）：① `CHAIN_REQUIRE` 为空时判据**不得自证**;② 两脚本零字面量;③ manifest 确定性。 |
| **D7** | **动态对照**（闸门跑，~3 分钟）：`tool → 0` **且** `text → 1` **同时成立**。记录**上次执行时间**,过期即报"对照已过期"——**一个很少跑的对照，本身就是一个未被持续行使的扩展点**（CI-144 §5）。 |
| **D8** | **证明只在结果层。** `ps eww` 读的是"我告诉了它什么",降级为**诊断**;证明一律取行为结果（派发 0/5→5/5、`nodes` 0→16–20）。 |

## 3. `resolved.json` 形状（**冻结**）

```json
{
  "components": { "<name>": { "port": 50061, "kind": "http" } },
  "panel_port": 50050,
  "anaphase_env": { "ANAPHASE_MIND_ENDPOINT": "http://127.0.0.1:50052", "...": "..." },
  "start_env": { "TUCK_GATEWAY__AUDIT_PATH": "<workspace>/.helix/tuck/audit.chain" },
  "counts": { "components": 7, "anaphase_env": 4 }
}
```

**确定性约束（缺一不可）**：键**递归排序**;值**不得**出现绝对路径（保留 `<workspace>`）;
**不得**出现时间戳/主机名/pid/build id;行尾与 locale 固定（`LC_ALL=C`）;末尾单个换行。
**脱敏规则**：只允许白名单键（`ANAPHASE_*` / 声明中 `start_env` 的键）;
**任何键名含 `KEY`/`TOKEN`/`SECRET` 者直接拒绝生成整个 manifest**（不是脱敏——脱敏会留下第二个真相来源）。
实测：当前 6 个键中含密钥键 **0** 个。

## 4. 顺序（**不可颠倒**）

**D4 → D3 → D5/D6 → 默认严格 + `unproven` 三档分诊 → 2b（GREASE）**

- **D4 不满足则不做 D5 的 tripwire**：`generate && git diff --exit-code` 会**永远非空** ⇒ 门永远红 ⇒ **被关掉**（"长期红着的门会失去权威"）。非确定性的头号来源正是时间戳与绝对路径。
- **默认严格与分诊必须同批**：那 5 条 `unproven` 各自落到
  **(a)** 补夹具 ⇒ `proven` / **(b)** 是"环境齐全才通过"的确定性缺陷 ⇒ **修** /
  **(c)** 本机确无该能力 ⇒ 声明 `requires`、**显式**移出默认集。
  **只有 (c) 是合法跳过，且必须可见、有名、有理由。**
- **2b 的 GREASE 探针带 `synthetic=true`,计量断言只统计真实流量**——刚把计量从"从没数据"修成"有数据",不能变成"有假数据"。

## 5. 诚实边界

1. **这条 E2E 证明的是"在这台机器上通",不是"从零能通"。** 横幅必须写明。
2. 四个**未管理依赖**（`.helix/events` 历史、registry 供应商、Tuck 审计链、**8080 上的 `llama-server`**）
   各落三档之一：由 harness 创建 / 声明为**带 owner 的外部前提** / 显式降级模式。
   "知道它存在"不算数——那是存在性证据。
3. **不承诺一个不会跑的干净重建作业**;稀有作业会腐烂。最低限度：把局限写进输出。

## 6. 执行纪律（**由一次真实事故得来**）

**任何改变默认值求值顺序的改动，必须真跑一次完整启动。**

实测（2026-09-24）：把面板默认端口写成 `PORT="${1:-$PORT_PANEL}"` 时，那一行在**派生之前**
执行，于是 `start-panel.sh` 从那一刻起就是坏的 —— `PORT_PANEL: unbound variable`。
**它坏了四五轮,而每一次运行都绕过了那条分支**：`--stop` 提前返回，`up` 走的是 Rust 侧，
静态判据只读文本。

```
./start-panel.sh: line 23: PORT_PANEL: unbound variable
```

**"覆盖了但没行使"**：脚本被 CI 触碰、被静态检查读过、被 lint 通过 —— 而那条真实分支
**一次都没被执行**。引导/启动类脚本是天然的低行使路径：它们在每台机器上只走一次完整启动。

⇒ 纪律：
1. **往既有脚本里插入一段代码 ⇒ 必须真跑那条路径**,不能用 `--stop`、`up` 或静态检查代替。
   ⚠️ **本纪律写下之后,我在同一个文件里又违反了一次**:把 `--self-check` 块插在 `HERE`
   **定义之前** ⇒ `line 28: HERE: unbound variable`。**`set -u` 第二次救场。**
   广义化的形式是：**新插入的代码不得依赖"稍后才定义"的东西**（默认值求值顺序、变量定义、
   函数定义），而检查它的唯一可靠办法就是**真跑**。
2. `set -u` 是 **fail-closed 在 shell 层的同构物** —— 它把"静默展开成空字符串"
   变成"当场在出错那行炸掉"，这次正是它救的场。**不要为了省事关掉它**；
3. 判据若为了适配实现而被改判（本 ADR 的 D3 就发生过），**必须附变异证明**：
   弄坏被断言的**结果**,判据必须重新变红。改判据比改数字更危险，因为它看起来更有道理。

## 7. 已完成的变异证明（供复核）

| 变异 | 期望 | 实测 |
