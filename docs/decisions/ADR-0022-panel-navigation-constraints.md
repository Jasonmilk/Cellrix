# ADR-0022: 面板导航约束（N 系列）——把「导航与流转」立为一个约束类别

- **状态**: Proposed（待人类批准）
- **日期**: 2026-09-17
- **决策范围**: Cellrix 面板（`web/assets/*`、`web/src/*`、`docs/spec/`）/ 人类可读的导航形态本身
- **关联**: `ADR-0018`（事件族装配层）、`ADR-0019`（事件流坐标）、`ADR-0021`（Web 面板的协议投影）、`DNA` 原则 3（碳硅同构）、`CAPABILITY-13` PC-2（`view_hash`，"what you see is what you sign"）、phyt-DNA v1.0（共享方法论）
- **引用约定**: 不带仓名的 `ADR-XXXX` 一律指 `Cellrix:ADR-XXXX`。

---

## 1. 背景

### 1.1 现状：导航从未被当作一个约束类别

面板的视图切换、列表、选择态、入口，**全部是逐处工程决定**，没有任何文档规定它们该遵守什么。已实现的部分（`DOM` 契约、事件族装配、证轨行可追溯）都有约束；**唯独"人怎么在面板里移动"没有。**

这与一个成熟的观察一致（不点名，只记事实）：**「导航与信息架构」是可视化界面体系里最容易整块缺失的维度**——因为它在"表皮"上看起来正常，坏起来也不报错。

### 1.2 实测到的缺陷（证据，非印象）

以下每条都在本仓代码或运行中的面板上核验过：

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | **同一列表渲染两遍，且点击语义不同** | `session.html` 对 `'s-side'` 与 `'chat-side'` 各调一次 `renderSide()`，靠 `chatMode` 分支决定点击行为 |
| 2 | **状态不可寻址**：无 URL/hash | 视图切换是 `Cx.showView()` 纯 JS 状态机 ⇒ 不能深链、不能后退、不能分享 |
| 3 | **「当前位置」有三个来源** | `st.chatJobId` / `window.__proveTrackMeta` / `Cx.selectPeriod()` |
| 4 | **卡片标题曾撞名 58/141** | `autoName` 只到分钟；同分钟内的不同对话标题完全相同（已修） |
| 5 | **4 个视图写死 + 手写 switch** | `#view-cockpit` / `#view-prove-track` / `#view-chat` / `#view-flows`；加视图必须动导航 |
| 6 | **零态有，错误态/加载态无出路纪律** | 零态存在（「尚无经历」）；无错误态/加载态的约束 |
| 7 | **破坏性操作无撤销路径** | 记忆删除经 CLI 生效后无 UI 撤销；`rename` 无害但亦不可逆 |

**注意 #1 与 #6 的性质**：它们不是"没做完"，而是**做完了但彼此不一致**——这正是缺少约束类别的典型症状。

### 1.3 为什么这不是"审美问题"

面板是 **`INTENT-7` §15 法定参考实现** + **`CAPABILITY-13` PC-2** 的参考实现（`ADR-0021` §背景）。PC-2 的契约是 **`SemanticSnapshot` + `view_hash`：what you see is what you sign**。而 **DNA 原则 3（碳硅同构）**要求：人类看到的视觉布局 = AI 看到的语义拓扑。

⇒ **一张卡承载什么、一次点击移动到哪里，都不是风格偏好，而是"人类签的那个视图是否等于真实拓扑"的一部分。** 导航错了，`view_hash` 就是错的。

---

## 2. 决策

### 2.1 新增约束类别：导航与流转（N 系列）

面板的导航不再由逐处工程决定，而由**一个显式的约束类别**规范。每条约束必须给出**来源类型**与**硬度**，并进入下表。**没有表内条目支撑的导航改动，不得合入。**

### 2.2 九个维度（缺一即结构性缺失）

| # | 维度 | 必须回答的问题 |
|---|---|---|
| 1 | 导航层级与广度 | 层级多深、同级多宽 |
| 2 | 位置感与寻路 | 人怎么知道自己在哪里 |
| 3 | 回溯与路径记忆 | 怎么回去、路径是否被记住 |
| 4 | 导航形态选择 | 容器/并列/抽屉/搜索，凭什么选 |
| 5 | 状态恢复与深链 | 刷新、分享、重进之后还在原处吗 |
| 6 | 出路设计 | 零态/加载态/错误态各自的出路 |
| 7 | 破坏性操作与撤销 | 什么会毁东西、怎么撤回 |
| 8 | 入口一致性与可预测性 | 同一事物是否只有一个入口、行为是否一致 |
| 9 | 无障碍导航 | 不用指针/低视力/运动障碍者能否完成同样的事 |

### 2.3 锚定表（含来源类型与硬度）

**来源类型**：`[派生自 <本仓原则/约束 ID>]` / `[新原语: 文献]` / `[平台行为: 版本]` / `[ENG]` / `[待锚定]`。
**硬度**：钻石（碳基生理/认知不可变边界 + 充分学术共识）/ 钢铁（硅基物理）/ 陶土（工程约定，**必标 `[ENG]`**）。

| # | 维度 | 约束 | 来源类型 | 硬度 |
|---|---|---|---|---|
| N-001 | 1 层级与广度 | 面板主视图数保持同级并列，不引入二级导航层 | `[派生自 DNA 原则 3]` + `[ENG]`（当前为 4，上限待定） | 钻石（同构要求）+ 陶土（数字） |
| N-002 | 1 层级与广度 | 同级导航项数量上限 | `[待锚定]` — **不设数字** | 陶土 |
| N-003 | 2 位置感 | 任意时刻存在**唯一**的「当前视图 + 当前 period」位置 | `[派生自 PC-2 view_hash]` | 钻石 |
| N-004 | 2 位置感 | 当前 period 必须在视图内可见地标示 | `[派生自 DNA 原则 3]` | 钻石 |
| N-005 | 3 回溯 | 视图切换必须可后退 | `[派生自 N-003]` + `[ENG]` | 钻石（公理级）+ 陶土（实现） |
| N-006 | 3 回溯 | 血缘路径（根→当前 period）必须可读 | `[派生自 ADR-0019 坐标]` | 钻石 |
| N-007 | 4 形态选择 | 视图装配走**槽位/注册**而非手写 switch | `[派生自 极致复用]` | 钻石（复用纪律）+ 陶土（形态） |
| N-008 | 4 形态选择 | 不用指针也能到达任一视图 | `[待锚定]` | 陶土 |
| N-009 | 5 状态恢复 | 视图 + period 可由 URL hash 完整表达（`#view=…&period=…`） | `[派生自 N-003]` + `[ENG]`（键值对形态） | 钻石（位置感）+ 陶土（形态） |
| N-010 | 5 状态恢复 | 畸形/陌生 hash **不得**导致面板不渲染 | `[派生自 容忍降级]` | 钻石 |
| N-011 | 6 出路 | 零态/加载态/错误态各自给出可执行出路 | `[派生自 N-010 同族]` + `[ENG]` | 钻石（不困住人）+ 陶土 |
| N-012 | 6 出路 | 无出路的状态不得发布 | `[ENG]` | 陶土 |
| N-013 | 7 破坏性操作 | 破坏性操作必须有撤销或二次确认 | `[派生自 铁律 1 的谨慎面]` + `[ENG]` | 钻石（不可挽回）+ 陶土（形式） |
| N-014 | 7 破坏性操作 | UI 与 CLI 的破坏能力必须分级且可见 | `[ENG]` | 陶土 |
| N-015 | 8 入口一致性 | **同一事物只有一个入口**；两个入口必须行为一致 | `[派生自 DNA 原则 3]` | 钻石 |
| N-016 | 8 入口一致性 | 同一操作的入口位置不得随视图变化 | `[派生自 N-015]` | 钻石 |
| N-017 | 8 入口一致性 | 卡片标题必须**稳定不漂移**（创建时冻结） | `[派生自 N-003]` + `[ENG]`（冻结实现） | 钻石（位置可信）+ 陶土 |
| N-018 | 9 无障碍 | 导航控件有可读名称与可达焦点 | `[待锚定]` | 陶土 |
| N-019 | 9 无障碍 | 状态变化（选中/展开）以非颜色方式可辨 | `[待锚定]` | 陶土 |

### 2.4 硬度纪律（**照抄会被固化，故必须自证**）

- **钻石**：仅当陈述的是**碳基生理/认知的不可变边界**，且有充分学术共识。
- **钢铁**：仅当陈述的是**硅基物理边界**（渲染管线、显示面板、能耗）。**平台机制不属钢铁**——它随版本与厂商决策变化（"某平台在某版本起把第 6 项折叠为 More"是**年度级行为**，不是物理定律）。平台行为走 `[平台行为: 版本]` 并带版本锚点 + 复审期。
- **陶土**：工程约定/行业惯例/项目基因。**必标 `[ENG]` 并说明推导逻辑。禁止把行业惯例包装成生理必然。**
- **任何量化阈值**：有文献/官方指南则标出处；是工程保守约定则标 `[ENG]`。

**⚠️ 一条本 ADR 特有的自律**：参照实践中存在一串文献锚定（认知负载、寻路、信息觅食等）。**本 ADR 不复制其中任何引用**——把未经本仓核验的引用搬进一份以"来源可追溯"为纪律的文档，**本身就是该纪律要治的冒充**。因此 N-002 / N-008 / N-018 / N-019 标 `[待锚定]` 且**刻意不给数字**：宁缺毋滥。

### 2.5 工具纪律（新增，且优先级高）

**校验器不得把 `[ENG]` 阈值写成硬断言。**

理由：**机器把陶土固化成钻石，比手写冒充更隐蔽。** 一条断言"视图数 = 4"或"列表 ≤ N 条"的测试，会把一个工程约定变成**看起来有测试保护的事实**，而后来者不敢改它。本仓刚扩过回归网（10 套），此风险已在眼前。

⇒ 校验器只许断言**来源类型为钻石的条目**；`[ENG]` 条目可以**报告当前值**，但不得**断言其为正确**。

## 3. 不做什么（Non-Goals）

- 不规定视觉风格（颜色、间距、字体）——那属于设计体系的取值范围，本 ADR 只管**流转**。
- 不规定具体前端框架或路由库。
- **不在本 ADR 内改代码**：本 ADR 只立约束类别与锚定表；接线（选择态 + hash）与槽位重构各自另批。
- 不为 N-002 / N-008 / N-018 / N-019 编造锚定。**空着是诚实的，填错是冒充。**

---

## 4. 验收

1. **锚定表完整性**：每条 N-xxx 都有来源类型与硬度；标 `[派生自 X]` 的，X 必须真实存在于本仓（**校验器输入**，查不到即冒充）。
2. **工具纪律**：回归网中不存在对 `[ENG]` 条目的硬断言（人工复核 + 加一条命名检查）。
3. **行为验收**（接线落地后）：`#view=…&period=…` 往返一致；畸形 hash 仍渲染；同一事物只有一个入口；后退可用。
4. **碳硅同构**：面板上"一张卡"与 `SemanticSnapshot` 里的一个语义单元一一对应（由 `ADR-0021` 的投影工作保证）。

## 6. 后果与风险

**正面**：导航首次有单一真相源；`view_hash` 的"所见即所签"有约束支撑；缺陷不再靠"看起来不对"发现；`[待锚定]` 明确承认未知，而不是用数字掩盖。

**代价与风险**：
- 约束类别会**增加改动的前置成本**：今后改导航要先落表内条目。这是有意的（决策先于代码），但会拖慢试错。
- `[待锚定]` 四条**目前无锚定**，若长期不补，本 ADR 的锚定表会有四行空转——**须设复审期限**（建议 30 天），到期未补则永久降级为 `[ENG]`，不许悬空。
- 硬度判定是**人判断**，本 ADR 只能给纪律、不能给算法。

## 7. 替代方案

| 方案 | 否决理由 |
|---|---|
| 只修具体缺陷，不立约束类别 | 缺陷会以新形态复发（已实证：#1 与 #6 就是"各自做完但互相不一致"） |
| 照抄参照实践的 N 系列与文献锚定 | 会连带搬入其**已被修订掉**的错误（其第一版的锚定表、钢铁定义、行数估计均被取代），且违反"来源须经本仓核验" |
| 把导航约束并入 `ADR-0021` | 0021 是**投影**（语义单元 ↔ 视图单元），导航是**流转**；两个类别，混则两者都说不清 |
| 先接线，约束后补 | 与本生态「决策先于代码」相反；且参照实践的第一版正是在锚定表上出错，**先写决策能挡住那类错** |

## 8. 待人类决策

1. **批准本 ADR？** 批准后转 Accepted，方可动 N1/N2。
2. **N-002「同级导航项上限」是否允许留空？** 本 ADR 的立场是**留空**（宁缺毋滥）。
3. **`[待锚定]` 的复审期限**：建议 30 天，到期未补则永久降级 `[ENG]`——是否照此？
4. **N-014「UI 与 CLI 破坏能力分级」**：面板是否需要**任何**破坏性操作？若答案为"永不需要"，该条可删除而非锚定。

---

*本 ADR 只立约束与锚定，不含代码改动。它的每一条缺陷陈述都附了本仓证据；它的每一处未知都标了 `[待锚定]` 而非填一个看起来专业的数字——因为把陶土说成钻石，是推导中最常见的欺诈。*
