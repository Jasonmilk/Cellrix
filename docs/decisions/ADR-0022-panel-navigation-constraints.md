- **日期**: 2026-09-17
- **决策范围**: Cellrix 面板（`web/assets/*`、`web/src/*`、`docs/spec/`）/ 人类可读的导航形态本身

## 1. 背景

### 1.1 现状：导航从未被当作一个约束类别

面板的视图切换、列表、选择态、入口，**全部是逐处工程决定**，没有任何文档规定它们该遵守什么。已实现的部分（`DOM` 契约、事件族装配、证轨行可追溯）都有约束；**唯独"人怎么在面板里移动"没有。**

这与一个成熟的观察一致（不点名，只记事实）：**「导航与信息架构」是可视化界面体系里最容易整块缺失的维度**——因为它在"表皮"上看起来正常，坏起来也不报错。

### 1.2 实测到的缺陷（证据，非印象）

以下每条都在本仓代码或运行中的面板上核验过：

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | **同一列表渲染两遍，且点击语义不同** | `session.html` 对 `'s-side'` 与 `'chat-side'` 各调一次 `renderSide()`，靠 `chatMode` 分支决定点击行为 |
| 2 | **状态不可寻址**：无 URL/hash | 视图切换是 `Cx.showView()` 纯 JS 状态机 ⇒ 不能深链、不能后退、不能分享 |
| 3 | **「当前位置」有三个来源** | `st.chatJobId` / `window.__proveTrackMeta` / `Cx.selectPeriod()` |
| 4 | **卡片标题曾撞名 58/141** | `autoName` 只到分钟；同分钟内的不同对话标题完全相同（已修） |
| 5 | **4 个视图写死 + 手写 switch** | `#view-cockpit` / `#view-prove-track` / `#view-chat` / `#view-flows`；加视图必须动导航 |
| 6 | **零态有，错误态/加载态无出路纪律** | 零态存在（「尚无经历」）；无错误态/加载态的约束 |
| 7 | **破坏性操作无撤销路径** | 记忆删除经 CLI 生效后无 UI 撤销；`rename` 无害但亦不可逆 |

**注意 #1 与 #6 的性质**：它们不是"没做完"，而是**做完了但彼此不一致**——这正是缺少约束类别的典型症状。

### 1.3 为什么这不是"审美问题"

面板是 **`INTENT-7` §15 法定参考实现** + **`CAPABILITY-13` PC-2** 的参考实现（`ADR-0021` §背景）。PC-2 的契约是 **`SemanticSnapshot` + `view_hash`：what you see is what you sign**。而 **DNA 原则 3（碳硅同构）**要求：人类看到的视觉布局 = AI 看到的语义拓扑。

⇒ **一张卡承载什么、一次点击移动到哪里，都不是风格偏好，而是"人类签的那个视图是否等于真实拓扑"的一部分。** 导航错了，`view_hash` 就是错的。

### 1.4 骨架借鉴的边界（人类裁定，2026-09-17）

人类裁定：**客户端骨架全部借鉴成熟实践**（多个灵感来源并列——DSH、Claude Code、Codex 等，**无单一权威**），**配色与自有 UI/UX 除外**；**不复制代码**。

**这条裁定的三条后果**：

1. **只借模型，自己实现。** 不复制任何代码 ⇒ 不触发许可证保全义务；但仍在本仓留一条**来源说明**——"Idea are not copyrightable; etiquette not obligation" 说的是**法律**上不必，不是**做人**上不必。
2. **不引入新构建体系/容器依赖。** 面板保持 **Rust + 纯 JS 资产经 `include_str!` 嵌入二进制**。把别的项目的 DI 容器与构建管线搬进来，等于换掉一条**已验证过**的链路（逐字节等价验证、`__REFRESH__` 顺序陷阱、随二进制一起构建），代价远超 UI 收益。⇒ 借**形状**，不借**容器**。
3. **理由自证。** 论证立在本仓原则上（碳硅同构 / PC-2 `view_hash` / 极致复用），外部实践只作**佐证**。`ADR-0021` 记录过反例：论证根基立在外部项目上，会让本仓**失去判断力**——而灵感来源越多，这条越关键。

**同一裁定暴露了本 ADR 的一处错误（已更正）**：N-001 原写「主视图数保持同级并列，不引入二级导航层」，把"层级最浅"当美德。**但"同级并列"恰恰固化了实际存在的"主次不清"**——四个视图等权，人不知道从哪开始。⇒ **用一条听起来正确的原则，把一个实际问题写成了规范**。N-001 据此改为「**存在唯一主视图**」，锚定由"层级浅"换成"**主任务单一**"。

**主任务主张（N-001 的依据）**：主 = **对话**（人与 Helix 交互之处）；辅助 = 证轨 / 流 / 仪表，降为同一主界面内的**侧板或抽屉**，不再与主平级；经历列表降为**层级**（线程 → 轮次）且当前线程高亮。
**这一处改动同时满足 N-003 / N-005 / N-009 / N-015** —— 因为它们本就是同一问题的四个面。

## 2. 决策

### 2.1 新增约束类别：导航与流转（N 系列）

面板的导航不再由逐处工程决定，而由**一个显式的约束类别**规范。每条约束必须给出**来源类型**与**硬度**，并进入下表。**没有表内条目支撑的导航改动，不得合入。**

### 2.2 九个维度（缺一即结构性缺失）

| # | 维度 | 必须回答的问题 |
|---|---|---|
| 1 | 导航层级与广度 | 层级多深、同级多宽 |
| 2 | 位置感与寻路 | 人怎么知道自己在哪里 |
| 3 | 回溯与路径记忆 | 怎么回去、路径是否被记住 |
| 4 | 导航形态选择 | 容器/并列/抽屉/搜索，凭什么选 |
| 5 | 状态恢复与深链 | 刷新、分享、重进之后还在原处吗 |
| 6 | 出路设计 | 零态/加载态/错误态各自的出路 |
| 7 | 破坏性操作与撤销 | 什么会毁东西、怎么撤回 |
| 8 | 入口一致性与可预测性 | 同一事物是否只有一个入口、行为是否一致 |
| 9 | 无障碍导航 | 不用指针/低视力/运动障碍者能否完成同样的事 |

### 2.3 锚定表（含来源类型与硬度）

**来源类型**：`[派生自 <本仓原则/约束 ID>]` / `[新原语: 文献]` / `[平台行为: 版本]` / `[ENG]` / `[待锚定]`。
**硬度**：钻石（碳基生理/认知不可变边界 + 充分学术共识）/ 钢铁（硅基物理）/ 陶土（工程约定，**必标 `[ENG]`**）。

### 2.4 硬度纪律（**照抄会被固化，故必须自证**）

- **钻石**：仅当陈述的是**碳基生理/认知的不可变边界**，且有充分学术共识。
- **钢铁**：仅当陈述的是**硅基物理边界**（渲染管线、显示面板、能耗）。**平台机制不属钢铁**——它随版本与厂商决策变化（"某平台在某版本起把第 6 项折叠为 More"是**年度级行为**，不是物理定律）。平台行为走 `[平台行为: 版本]` 并带版本锚点 + 复审期。
- **陶土**：工程约定/行业惯例/项目基因。**必标 `[ENG]` 并说明推导逻辑。禁止把行业惯例包装成生理必然。**
- **任何量化阈值**：有文献/官方指南则标出处；是工程保守约定则标 `[ENG]`。

**⚠️ 一条本 ADR 特有的自律**：参照实践中存在一串文献锚定（认知负载、寻路、信息觅食等）。**本 ADR 不复制其中任何引用**——把未经本仓核验的引用搬进一份以"来源可追溯"为纪律的文档，**本身就是该纪律要治的冒充**。因此 N-002 / N-008 / N-018 / N-019 标 `[待锚定]` 且**刻意不给数字**：宁缺毋滥。（这四条随后在 **§2.4b 全部定级**，锚定表已无 `[待锚定]` 行。）

### 2.4b 双标注纪律（补全 `[待锚定]` 时得到的规则）

凡是「无障碍」与「可达性」类约束，**必须拆成两半分别定级**：

- **生理 / 认知基础**那半 ⇒ **钻石**（碳基不可变边界：运动障碍、低视力、色觉差异等）；
- **条款 / 机制实现**那半 ⇒ **陶土 `[ENG]`**（合规契约、焦点顺序、键位、实现细节）。

**最忌把条款本身当锚定**：合规条款是**契约**，不是**生理事实**；拿它去支撑"钻石"，就是把陶土说成钻石——只是换成了一份看上去权威的文件。这条纪律用于补全 N-008 / N-018 / N-019，并使它们由 `[待锚定]` 变为**可判定**。

**N-002 保持不给数字**：即使参照同类判定，单一实验得出的数量比值**不构成"充分学术共识"**，故只能标陶土且**不得升格**。**"留空"与"填一个看起来专业的数字"之间，本 ADR 选留空。**

### 2.5 工具纪律（新增，且优先级高）

**校验器不得把 `[ENG]` 阈值写成硬断言。**

理由：**机器把陶土固化成钻石，比手写冒充更隐蔽。** 一条断言"视图数 = 4"或"列表 ≤ N 条"的测试，会把一个工程约定变成**看起来有测试保护的事实**，而后来者不敢改它。本仓刚扩过回归网（10 套），此风险已在眼前。

⇒ 校验器只许断言**来源类型为钻石的条目**；`[ENG]` 条目可以**报告当前值**，但不得**断言其为正确**。

## 3. 不做什么（Non-Goals）

- 不规定视觉风格（颜色、间距、字体）——那属于设计体系的取值范围，本 ADR 只管**流转**。
- 不规定具体前端框架或路由库。
- **不在本 ADR 内改代码**：本 ADR 只立约束类别与锚定表；接线（选择态 + hash）与槽位重构各自另批。
- 不为 N-002 / N-008 / N-018 / N-019 编造锚定。**空着是诚实的，填错是冒充。**

## 4. 验收

1. **锚定表完整性**（**校验器已落地**：`tools/adr_anchor.js`，2026-09-17，经变异注入证明非空转）：每条 N-xxx 都有来源类型与硬度；表内 `[派生自 N-xxx]` 必须指向**表内存在**的条目；文本中出现的每个 `ADR-XXXX` 必须解析到**生态内某个仓**的真实文件（跨仓引用按事实解析 —— 见文首引用约定，不按仓名缺省重解）。
   **断言得起的与断言不起的**：本仓没有「原则登记表」，所以 `[派生自 容忍降级]` 这类**短语锚定只报告、不判真伪**——给它们现编一张登记表，就等于发明锚定，正是 §2.4 要治的那件事。这条边界写在校验器文件头，不是留白。
2. **工具纪律**：回归网中不存在对 `[ENG]` 条目的硬断言（人工复核 + 加一条命名检查）。
3. **行为验收**（**已落地，2026-09-17**）：`#view=…&period=…` 往返一致；畸形 hash 仍渲染；同一事物只有一个入口；后退可用。由 `web/tests/all_views_test.js` 对真面板驱动，并经变异注入证明非空转。
4. **碳硅同构**：面板上"一张卡"与 `SemanticSnapshot` 里的一个语义单元一一对应（由 `ADR-0021` 的投影工作保证）。
5. **出路完整性**（N7 落地后）：不存在「只报告、不给路」的状态；出路由**一个**解析器从语义状态产出，四处视图共用（静态扫描 + 解析器全域性，变异注入证明）。

| **N7** ✅**已排期** | 出路设计（维度 6）：零态/加载态/错误态各自的出路由**一个**解析器从语义状态产出，四处视图共用（N-011/N-012） | N2 |

> **更正记录（2026-09-17，不重写历史）**：原 §5 只有 N0–N6，**维度 6（出路设计 N-011/N-012）与维度 9（无障碍 N-018/N-019）没有任何一期** —— 有约束、无分期，等于**永远不会被排期**。而 §1.2 缺陷 #6 说的恰恰就是「错误态/加载态无出路纪律」，它却在自己的分期表里没有位置。这与 §8#3 是同一类错误的两个面：**锚定表和分期表必须互相覆盖**，否则「立了约束」只是一句话。补为 N7/N8。

**N1 刻意排在 N2 之前**：先确保"校验器不会把陶土固化成钻石"，再动接线——否则接线的测试本身可能成为下一处固化源。

## 6. 后果与风险

**正面**：导航首次有单一真相源；`view_hash` 的"所见即所签"有约束支撑；缺陷不再靠"看起来不对"发现；`[待锚定]` 明确承认未知，而不是用数字掩盖。

**代价与风险**：
- 约束类别会**增加改动的前置成本**：今后改导航要先落表内条目。这是有意的（决策先于代码），但会拖慢试错。
- ~~`[待锚定]` 四条**目前无锚定**，若长期不补，本 ADR 的锚定表会有四行空转——须设复审期限~~ → **已消解**：四条在 N6 全部定级（§2.4b），锚定表无空转行，不需要复审期限。**保留此条留痕**：它暴露的不是「有未知」，而是**未知没有回收机制**。
- **另一种悬空（2026-09-17 实测暴露，已补）**：锚定表与分期表**必须互相覆盖**。原 §5 只到 N6，漏排维度 6/9，于是 N-011/N-012/N-018/N-019 **有约束、永不排期**——「立了约束」变成一句空话。锚定表那一侧现在由 `tools/adr_anchor.js` 断言；**分期表那一侧仍靠人复核，这是本 ADR 剩余的最大人工负担**，如实记下而不是假装已解决。
- 硬度判定是**人判断**，本 ADR 只能给纪律、不能给算法。

## 7. 替代方案

| 方案 | 否决理由 |
|---|---|
| 只修具体缺陷，不立约束类别 | 缺陷会以新形态复发（已实证：#1 与 #6 就是"各自做完但互相不一致"） |
| 照抄参照实践的 N 系列与文献锚定 | 会连带搬入其**已被修订掉**的错误（其第一版的锚定表、钢铁定义、行数估计均被取代），且违反"来源须经本仓核验" |
| 把导航约束并入 `ADR-0021` | 0021 是**投影**（语义单元 ↔ 视图单元），导航是**流转**；两个类别，混则两者都说不清 |
| 先接线，约束后补 | 与本生态「决策先于代码」相反；且参照实践的第一版正是在锚定表上出错，**先写决策能挡住那类错** |
