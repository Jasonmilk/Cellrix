# ADR-0046: 面板默认端口必须避开 llama.cpp 的默认端口（8080 → 50050）

- **状态**: Proposed
- **日期**: 2026-09-24
- **决策范围**: `WEB_PORT_DEFAULT`（`web/src/config.rs` / `web/src/bin/up.rs`）与各测试的默认
  `CELLRIX_PANEL`、README 中的默认端口
- **相关**: `Cellrix:ADR-0014`（web 面板；它记录的是"协议默认 8080"这件事在当时成立）、
  `Cellrix:ADR-0045`（探针必须读状态行）、`anaphase:ADR-0046`（唯一接线声明）
- **注意编号**: 本仓与 `anaphase-helix` 各有一份 `ADR-0046`,内容不同。跨仓引用**必须带仓名**
  （本生态既有纪律）。

## 1. 问题（实测，2026-09-24）

`Cellrix:ADR-0014` 把 `8080` 定为面板协议默认。**8080 是 llama.cpp / `llama-server` 的默认端口**,
也是无数本地服务的默认端口。在这台机器上实测：

```
$ lsof -nP -iTCP:8080 -sTCP:LISTEN
llama-ser 82885 jason 3u IPv4 ... TCP 127.0.0.1:8080 (LISTEN)
```

它不是"可能撞",是**已经在撞**。后果不是一条清晰的错误，而是**误导性的红**：
`all_views_test.js` 把 8080 上那个**不是面板**的页面塞进 jsdom，崩在它第 9 行的动态
`import()` 上（`ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`）—— 报告得像"面板坏了"。

这与 `Cellrix:ADR-0045` 是**同一条病的第二个实例**：那次是探针**不看状态行**就算健康;
这次是探针**不看身份**就算可用。"有东西应答"被读成了"是它"。

## 2. 决策

面板默认端口 `8080` → **`50050`**。

选 50050 的理由（按重要性）：
1. **不在任何常见默认端口之列**，尤其不与 llama.cpp 相撞；
2. **落在本生态自家的编排段**：tentacle `50051` / mind `50052` / anaphase `50061` /
   tuck `60052` / flowmodus `60053`·`60054` —— 面板紧邻链条，而不是漂在一个公共端口上；
3. 空着（`lsof` 实测）。

## 3. 只改"当前默认",不改历史

- **改**：两处常量、三处测试默认值、README 的默认端口说明。
- **不改**：`ADR-0014` / `ADR-0015` / `docs/archive/` / `GROWTH.md` 里的 `:8080` ——
  它们是**当时的记录**,当时是真的。改写它们等于篡改历史，而本生态对"历史可证"的要求
  正是靠这些不可改写的记录撑着的。
- 需要说明新旧关系的地方（`run_all.js` 的一条注释）**加注而不替换**。

## 4. 判据

- `all_views_test.js` 的**身份探针**（`base.html` 的根元素 `id="uxApp"`）在端口答错身份时
  给出 `NEEDS-INPUT` 而非红 —— 这条**先于**本决策落地（`Cellrix:7fc90a3`），
  正是它把这次撞端口从"崩"变成"指名道姓地说不是面板"。
- 面板在 50050 上起来后，`all_views_test.js` 应当**全绿**（而不是"未证"）。

## 5. 遗留（本决策**不**关闭）

**面板不在 `anaphase:ADR-0046` 的接线声明里。** `chain.json` 声明了六个组件
（tuck/tentacle/mind/flowmodus-serve/flowmodus-reason/anaphase），**面板不在其中**,
于是它的端口由各处的常量各自陈述——**这正是 ADR-0046 要消灭的形状**。

把面板加入声明**不是**加一行就够：`chain_wiring_test.js` 断言"启动器不得在可执行行里复述
已声明的端口",而 `start-panel.sh` 现在就持有面板端口 ⇒ 要么一并把该脚本改成派生，
要么声明与复述并存（后者会当场让判据变红）。因此这是一笔独立的工作，
**不与本次端口迁移混做**。
