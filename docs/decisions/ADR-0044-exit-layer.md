# ADR-0044: 出路层 —— 出路是状态的投影，所以只有一个解析器

- **状态**: Proposed（待人类批准；人类已于 2026-09-17 确认分期与形状，本文件是把它落成决策）
- **日期**: 2026-09-17
- **决策范围**: Cellrix 面板（`web/assets/*`）/ 四种状态（零态·加载态·错误态·受阻态）到「文案 + 动作」的映射
- **关联**: `ADR-0022`（导航约束 N 系列 —— 本 ADR 落实其 **N7 / N-011 / N-012**）、`ADR-0018`（事件族装配层：一条带子）、`ADR-0021`（Web 面板的协议投影）、`DNA` 原则 3（碳硅同构）、`DNA` 原则 6（极致复用）、`DNA` 铁律 2（400 行红线）
- **引用约定**: ADR 编号在 Helix 生态统一分配；跨仓引用必须带仓名（见 `ADR-0022` 文首）。

---

## 1. 背景

### 1.1 约束早就立了，落地没有形状

`ADR-0022` 的 N-011 要求「零态/加载态/错误态各自给出**可执行出路**」，N-012 要求「无出路的状态不得发布」。两条都是钻石/陶土双标注，却一直没有说**出路由谁产出**。结果是每个视图各自拼自己的失败文案，四条约束退化成四种习惯。

### 1.2 实测到的现状（逐行核对，非印象）

判据：**一个「只把失败讲给用户、不提供任何可执行动作」的渲染点 = 一处死胡同**。

| # | 站点 | 现在给用户看什么 |
|---|---|---|
| 1 | `script.html:270` | `snapshot 拉取失败: <e>` |
| 2 | `script.html:287` | `生态探测不可用（proxy 未就绪）` |
| 3 | `prove_track.js:231` | `Load failed: <e.message>` |
| 4 | `session.html:70` | `经历列表拉取失败: <e.message>` |
| 5 | `session.html:326` | `历史加载失败: <e.message>` |
| 6 | `session.html:258` | `事件全部被拒收（未知类型或格式不符）` |
| 7 | `session.html:373` | `经历列表拉取失败` |
| 8 | `session.html:224/228` | `重命名失败: <…>`（toast，5 秒自动消失）|
| 9 | `chat.js:223` | `发送失败: <e.message>`（toast）|
| 10 | `chat.js:175` | `<j.error>` 原文透传（toast）|
| 11 | `flows.html:120/121` | `路由决策失败: <cur.error>` + badge「不可用」|
| 12 | `gleam.html:198` | `审计 N 违约`（明细藏在 `title` 属性里）|

**另有 1 处不是死胡同而是缺零态**（单列，不混入上面的计数）：`prove_track.view.js:123` —— 选中经历但可渲染行为 0、或搜索无命中时，`#eTbody` 直接留白。

**已有出路、作为对照不动**：`script.html:252`（检查 up）、`session.html:65`（说话 / 配置项）、`flows.html:110`（刷新按钮）、`flows.html:117`·`159`（给出 flag 名）、`flows.html:141`（给出命令）。

**一处更正记录**：`script.html:93`「事件流读取异常——不猜测」**不是死胡同站点**，它是被 `throw` 的**来源**，最终由 #3 / #5 渲染。按站点计数它是 0 处。

### 1.3 为什么这不是文案问题

`DNA` 原则 3 要求「不允许**人类可见但 AI 不可寻址**的元素」。一句手写的「失败: <原始异常>」正是这种元素：它是给碳基看的字符串，在语义拓扑里没有对应物，AI 无法据它判断「这一屏是不是卡住了」。

**而一个动作天然是可寻址的结构**（它有 code、有目标、有前置条件）。所以：**把「说一句」换成「给出路」，本身就是把不可寻址之物换成可寻址之物。**

## 2. 决策

### D1 出路是**语义状态的投影**，不是视图的文案

四下视图不得各自决定失败时说什么。**一个解析器**从状态算出「这是哪一类、一句话、一个动作」。四处共用。

理由：这已是本仓反复验证过的形状（`ADR-0018` 一条带子对应多个目标；`ADR-0021` 一次投影对应多个视图单元）。出路若每视图一份，就是同一事实的多份推导——正是 `ADR-0018` 存在的原因。

### D2 词表归解析器，**能力归站点**

站点把「怎么重试」的函数**传进来**，解析器只决定「说什么、按钮叫什么」。

理由：反过来做（解析器知道每个视图的内部函数）会造出一个上帝对象，破坏 `DNA` 原则 2（极致解耦），并让解析器随视图增长而无界膨胀。传函数则解析器保持**零依赖、可单测、与 DOM 无关**。

### D3 失败先归类为 `code`，原始信息降级为 `detail`

站点负责把异常归类；解析器按 code 给词。**原始异常文本不再直接透给用户**，而是作为可展开的 `detail` 保留。

理由：原始异常对使用者无行动含义（#1–#12 全是这个形状）；但它对诊断有价值，所以**降级而非丢弃**。这条有边界：**当某故障确实无法归类、且原始信息比分类更有用时，应同时给出原文与一条出路，而不是二选一**（见 §3 非目标）。

### D4 三条不变量（可机器检查）

1. **解析器全域性**：已注册的每个 code 都返回非空文案；`kind === 'error'` 必带非空动作。
2. **站点不得手写失败文案**：`assets/` 中不存在绕过解析器的失败字符串。
3. **双向覆盖**：每个 code 至少被一个站点引用；每个站点都归到某个 code。**没有写了没人用的 code，也没有未归类的死胡同。**

### D5 toast 需要动作槽

`script.html` 的 `showToast` 目前是「5 秒自动消失、无按钮」。**错误走 toast 就永远给不出路**，因此 D4 的第 2 条无法在 #8/#9/#10 三处成立。

决策：toast 增加一个可选动作槽；**带动作的 toast 不自动消失**（自动消失与「给出路」在语义上矛盾）。

### D6 借来的形状必须带「过期条件」

骨架借鉴成熟实践的裁定已在 `ADR-0022` §1.4。本 ADR 把它压到**单个形状**的粒度：每借一个形状，记三行 —— 借的是什么、为什么适配本仓、**什么情况下该丢掉**。

| 借的形状 | 为什么适配本仓 | 什么情况下该丢掉 |
|---|---|---|
| 空态即**唯一** CTA | N-011 要求零态有出路；且动作可寻址，文案不可（§1.3）| 同一状态下存在两个同等重要的对等动作时（做两个并列入口，不硬选一个）|
| 错误按 **code** 给不同「下一步」| 现有 12 处「失败: <raw>」；且 `ADR-0019` 的坐标要求可追溯，**分类后的 code 才是可追溯事实** | 故障确实无法归类且原文更有用时（那时同时给原文与出路）|
| **下一步即占位符**：禁用时说明原因，并保留能解锁它的控件可点 | `session.html:213` 的保存键 disabled 无文案；`flows.html` 的「未配置（--flag）」已部分如此 | 解锁控件本身不可达时（配置在启动参数、须重启）——给**命令**并写明须重启，不给按钮 |
| **折叠物的再入口放在使用它的表面** | N3 将把证轨/流/仪表降为抽屉；收起后即够不着，与 `ADR-0018 D5`「不激活即不构建」同族 | 被收起之物有多个、入口互相淹没时（集中到一个视图菜单）|

**一条自我更正**：「加载/空/失败三态不合并」曾被列为借来的形状 —— **它不是借来的，它是 N-011 原文**。那叫落实，不叫借鉴。把它混进这张表会让本 ADR 看起来比实际更有外部依据，故删去。

## 3. 不做什么（Non-Goals）

- **不改导航结构**：合并侧栏与主视图主张属 N3（`ADR-0022` §5）。
- **不引路由库、不引构建体系**：解析器是一个纯 JS 资产，仍走 `include_str!` 嵌入（`ADR-0022` §1.4 后果 2）。
- **不做本地化字典工程**：本面板是中文界面，词表就是词表；引入以某种语言为键源的字典工程是换掉一条已验证的链路，代价远超收益。
- **不追求「所有错误都能归类」**：无法归类时**保留原文并同时给一条出路**，不假装它有分类。

---

## 4. 验收

1. **N-011 / N-012 行为验收**：12 处死胡同全部给出可执行动作；`#eTbody` 补零态。
2. **D4 三条不变量**各由测试断言，且**各以变异注入证明非空转**：
   - 删掉某 code 的动作 ⇒ 全域性测试红；
   - 在 `session.html` 手写一句失败文案 ⇒ 静态扫描红；
   - 加一个未注册的 code（或删掉一个仍有站点的 code）⇒ 双向覆盖测试红。
3. **活断言**：把 `fetch` 换成一律失败的代理再开一个 jsdom，断言面板仍渲染**且页面上存在至少一个可点动作**。这条直接证明 N-011，并可被变异证伪。
4. **400 行红线**（`DNA` 铁律 2）：新增资产 < 400 行；受改动的既有资产不得越线。**`session.html` 现为 392 行，是本次最紧的一处**——若 P1b/P1c 使其增长即须先解耦。

---

## 5. 后果与风险

**正面**：四种状态第一次有单一产出点；「无出路的状态不得发布」由一句纪律变成一条可运行的断言；失败文案里的原始异常从「给用户看的」降级为「可展开的诊断」，这是 N-011 与 `ADR-0019` 同时受益的一处。

**代价与风险**：
- 归类需要判断（某个 `500` 是「服务未起」还是「配置错」）。解析器只能给词表，**分类责任仍在站点**——如实记下，不假装已解决。
- 多一层间接：改一句文案要动词表而不是就地改字符串。这是有意的（同一句话只许有一处），但会拖慢微调。
- `showToast` 加动作槽会改变现有 5 秒自动消失的行为。**带动作不自动消失**是一条新约定，需要人类确认（见 §7）。

## 6. 替代方案

| 方案 | 否决理由 |
|---|---|
| 每个视图各自写自己的出路文案 | 就是现状。已实测出 12 处不一致（§1.2），缺陷会以新形态复发 |
| 只把 12 处文案改好，不建层 | 改完即散：下一次新增视图不会有任何东西提醒它给出路。N-012「不得发布」将无处生效 |
| 把出路塞进 `script.html` | `script.html` 已 347 行，400 行红线在即；且出路不是壳的职责（壳管生命周期，不管视图的词） |
| 引入成熟的 i18n/词表框架 | 换掉已验证的资产链路（`ADR-0022` §1.4 后果 2），为一件「一句话只有一处」的事付整套容器代价 |
